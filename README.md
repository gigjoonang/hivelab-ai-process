# HIVELAB 디자인 AI 프로세스

UI 구축 작업을 AI와 같이 하는 방법을 정리해 둔 저장소입니다.

프로세스 자체는 건드리지 않았습니다. 하던 순서, 내는 산출물, 고객사와 주고받는 방식 전부 그대로고, 각 단계 밑에 AI가 할 수 있는 일을 붙였습니다. 달라지는 건 단계마다 드는 시간과 비용입니다.

## 처음 오셨으면

들어 있는 건 두 가지입니다. 문서하고 스킬.

문서는 무엇을 언제 어떤 기준으로 하는지 정해 둔 쪽이고, 스킬은 그 자리에서 실제로 일을 하는 쪽입니다. Claude Code에서 `/스킬이름`으로 부릅니다.

문서 없이 스킬만 쓰면 사람마다 결과가 다르게 나옵니다. 반대로 문서만 있고 스킬을 안 쓰면 빨라지는 게 하나도 없고요. 둘 다 씁니다.

### 프로젝트 하나 시작하기

```bash
./bin/new-project.sh 프로젝트명
```

`projects/프로젝트명/` 폴더가 생기고 템플릿 8종이 복사됩니다. 거기 `source/`에 기획 문서를 넣고 (PDF든 워드든 PPT든 상관없습니다) Claude Code에서 순서대로 실행하면 됩니다.

```
/ui-intake      프로젝트 등록, 기획 문서 수령 확인
/ui-analyze     기획 문서 분석, 전략 잡기              (1-1)
/ui-structure   IA, 화면 목록, 레이아웃 3안            (1-2)
/ui-style       레퍼런스 수집, 스타일 3방향            (1-3)
─────── 방향 확정. 여기는 사람이 고릅니다 ───────      (1-4)
/ui-tokens      디자인 토큰 확정                      (2-0)
/ui-draft       컨셉 → 컴포넌트 → Figma B급 시안       (2-1)
/ui-assets      디자인 에셋, 생성 프롬프트             (2-3)
/ui-review      B급 시안 컨펌         [10/31 작성 예정] (2-2)
/ui-handoff     검수·정리·스타일가이드 [10/31 작성 예정] (3-1)
```

전체 흐름이랑 각 단계를 언제 끝난 걸로 볼지는 [WORKFLOW.md](WORKFLOW.md)에 한 장으로 정리해 뒀습니다. 그것부터 보세요.

## 꼭 지킬 것 네 가지

프로젝트 사정이 어떻든 이 넷은 안 바뀝니다.

**1. 고객에게 나가는 완성도는 사람이 책임집니다.**
AI가 만든 것(B급 시안, 생성 에셋)은 검수하고 손보기 전에는 고객사로 안 나갑니다.

**2. 앞 단계 파일이 비어 있으면 다음으로 안 넘어갑니다.**
앞이 비면 뒤 단계의 AI가 알아서 추측으로 채웁니다. 그 순간부터는 프로세스를 돌리는 의미가 없어집니다.

**3. 왜 골랐는지 적어둡니다.**
각 템플릿의 `결정 기록` 칸이요. 안 적어두면 두 달 뒤에 아무도 기억 못 합니다. 이 프로세스에서 조직에 실제로 남는 건 이 칸입니다.

**4. 고객사 자료는 이 저장소랑 승인된 도구 밖으로 안 나갑니다.**
자세한 건 [docs/00-principles.md](docs/00-principles.md)의 보안 항목에 있습니다.

## 용어 두 개

**A급 시안**: 고객 제안의 메인 안입니다. 브랜드를 어떻게 해석했고 뭐가 다른지가 들어가는 안이라 디자이너가 직접 만듭니다. AI는 에셋 만드는 것만 돕습니다.

**B급 시안**: 비교해 보라고 같이 내는 안입니다. AI가 만들고 사람이 골라서 손봅니다.

B급이 A급을 대충 만든 버전은 아닙니다. 원래 시간이 없어서 못 만들고 버렸던 안이에요. 품질을 낮추자는 게 아니라 볼 수 있는 선택지를 늘리자는 쪽입니다.

자세한 건 [docs/00-principles.md](docs/00-principles.md)에 있습니다.
