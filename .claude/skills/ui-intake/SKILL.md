# 0 · 착수

프로젝트 하나를 이 프로세스 위에 올리는 스킬이다. 여기서 만든 폴더랑 기본정보를 이후 모든 단계가 입력으로 받는다.

전체 흐름은 `WORKFLOW.md`, 원칙은 `docs/00-principles.md`를 따른다. 기준을 이 파일로 복사하지 말고 그쪽을 가리킨다.

## 순서

### 1. 프로젝트 폴더

`projects/[프로젝트명]/`이 이미 있으면 그걸 쓰고, 없으면 만든다.

```bash
./bin/new-project.sh [프로젝트명]
```

폴더명은 `고객사-프로젝트성격` 형식을 권한다. 공백 대신 하이픈.

### 2. 기획 문서 확인

`projects/[프로젝트명]/source/`에 문서가 있는지 본다. 없으면 어디 있는지 묻고 `source/`로 옮기게 한다. 대화에 첨부만 돼 있고 폴더에 없으면 다음 사람이 이어받을 수가 없다.

형식별로 읽는 방법:
- PDF → `pdf` 스킬
- 워드(.docx) → `docx` 스킬
- 파워포인트(.pptx) → `pptx` 스킬
- 노션이나 웹 내보내기 → 그냥 읽기

이 단계에서는 문서를 읽지 않는다. 읽을 수 있는지랑 분량, 목차 수준만 본다. 내용 분석은 1-1의 일이다.

### 3. 기본정보 채우기

`00-brief.md`의 `프로젝트 기본정보` 표를 채운다. 문서에서 알 수 있는 건 문서에서 가져오고, 나머지는 사용자에게 묻는다.

빈칸을 남기지 않는다. 모르는 건 `미정: [누구]에게 [언제] 확인` 형태로 적는다.

사용자에게 물어볼 것 (AskUserQuestion으로 한 번에 묶는다):
- 고객사 / 프로젝트명 / 산업군
- NDA 유무. 있으면 이후 전 단계에서 고객사명 웹 검색을 안 한다
- 시안 제출일 / 최종 납품일
- 최종 결정권자

### 4. 다음으로

기본정보가 채워지면 바로 물어본다.

> "기본정보 고정했습니다. 기획서 분석(1-1)으로 넘어갈까요?"

동의하면 `ui-analyze`를 부른다. 사용자가 이미 "알아서 끝까지 진행해달라"고 했으면 묻지 말고 바로 넘어간다.

## 주의

- 여기서 디자인 얘기를 시작하지 않는다. 착수는 사실 확인이다.
- 기획 문서가 아직 없으면 여기서 멈춘다. 문서 없이 1-1을 시작하면 전부 추측이 된다.
- NDA가 있으면 `00-brief.md` 상단에 표시하고, 사용자에게 "이 프로젝트에서는 고객사명으로 웹 검색을 하지 않습니다"라고 알린다.
