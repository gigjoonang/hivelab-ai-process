# 2-0 · 토큰

상세는 `docs/02-stage-build.md`의 2-0 항목, 명명 규칙은 `docs/design-system-rules.md`. 둘 다 읽고 시작한다.

입력은 `02-design-style.md`의 확정 방향, 채우는 파일은 `03-design-tokens.md`.

## 시작 전에

`01-ui-structure.md`랑 `02-design-style.md`의 `확정` 표가 둘 다 채워져 있어야 한다. 하나라도 비어 있으면 멈추고 알린다.

> "아직 방향이 확정 안 됐습니다. [구조 / 스타일]을 먼저 골라주세요. 지금 진행하면 토큰을 다시 잡게 됩니다."

사용자가 "일단 진행해달라"고 하면 진행하되, `03-design-tokens.md` 상단에 `방향 미확정: 재작업 가능성 있음`이라고 적어둔다.

## 왜 이 순서인가

지금까지는 화면을 다 그리고 나서 시스템을 정리했다. 그건 전 화면을 다시 만지는 일이다. 시안 전에 정해두면 한 번만 정하면 된다. 이 프로세스에서 기존이랑 순서가 달라지는 건 여기 하나뿐이다.

## 순서

### 1. 기존 시스템 확인

고객사에 디자인 시스템이 이미 있는지 `00-brief.md`에서 본다. 있으면:
- 새로 만들지 않는다. 기존 토큰을 그대로 받아 적는다
- 이 프로젝트에서 더 필요한 것만 `신규` 표시로 붙인다
- `03-design-tokens.md` 상단에 `명명 규칙: 고객사 시스템 준수`라고 적는다
- Figma Dev Mode MCP를 쓸 수 있으면 `get_variable_defs`로 기존 변수를 읽어온다

### 2. 토큰 채우기

`03-design-tokens.md`의 표를 전부 채운다. `02-design-style.md`의 확정 방향에서 컬러랑 타이포 성격을 가져온다.

값까지 정한다. "파란색 계열"은 토큰이 아니다.

- 원시값(neutral 8단)이랑 의미값(text-primary 등)을 나눈다. 의미값이 원시값을 참조한다
- Neutral 8단을 줄이지 않는다. 부족하면 시안에서 임의 색이 생긴다
- 타이포는 국문 기준으로 정하고 영문을 맞춘다. 반대로 하면 국문이 깨진다
- 간격은 4 또는 8 배수 하나로 통일
- 반경이랑 그림자는 각각 3단 이내
- 그리드는 `01-ui-structure.md` 값을 그대로 옮긴다. 여기서 새로 정하지 않는다

### 3. 대비 재기

`03-design-tokens.md`의 대비 검사 표를 채운다.

감으로 수치를 쓰지 않는다. 실제로 계산한다. 상대 휘도 공식으로 계산하는 스크립트를 Bash로 만들어 돌리는 게 제일 확실하다.

```
본문 텍스트                          4.5:1 이상
큰 텍스트(18.66px+ Bold 또는 24px+)   3:1 이상
UI 요소 경계, 아이콘                  3:1 이상
```

미달하면 그 자리에서 값을 조정한다. 시안 단계로 미루면 전 화면에 퍼진 다음에 발견된다.

### 4. 폰트 라이선스

웹폰트 사용 범위(웹 전용 / 앱 포함 / 임베딩)를 제작사 공식 페이지에서 확인하고, 출처랑 확인일을 `03-design-tokens.md`에 적는다.

기억으로 답하지 않는다. 라이선스 조건은 낙관적으로 잘못 기억되는 대표 항목이다.

### 5. 보여주고 다음으로

토큰 표 요약, 대비 검사 결과, 미달해서 조정한 내역을 보여준다.

"시안 제작(2-1)으로 넘어갈까요?" 하고 묻는다. 동의하면 `ui-draft`를 부른다.

## 주의

- 토큰이 정해지면 시안에서 그 밖의 값을 쓰지 않는다. 벗어나고 싶으면 이 파일부터 고친다.
- 다크 모드가 범위에 있으면 의미값을 두 벌 만든다. 원시값은 한 벌이다.
- 이 파일이 나중에 고객사 스타일가이드(3-1)의 원본이 된다. 성실히 채울수록 그때 일이 줄어든다.
