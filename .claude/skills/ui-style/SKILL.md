# 1-3 · 스타일

상세 절차는 `docs/01-stage-analysis.md`의 1-3 항목, 레퍼런스 규칙은 `docs/reference-rules.md`. 둘 다 읽고 시작한다.

레퍼런스 수집 기준은 `docs/reference-rules.md` 한 곳에만 둔다. 이 파일로 복사하지 않는다.

입력은 `00-brief.md`랑 `01-ui-structure.md`, 채우는 파일은 `02-design-style.md`랑 `drafts/reference-gallery.html`.

## 시작 전에

- `01-ui-structure.md`의 확정 표가 비어 있으면 `ui-structure`를 먼저 부른다.
- `00-brief.md`의 NDA 칸이 `있음`이면 고객사명으로 웹 검색을 하지 않는다. 산업군이랑 톤 키워드로만 찾는다.

## 순서

### 1. 브랜드 단서

`00-brief.md`에서 회사명, 산업군, 타겟, 기존 브랜드 자산, 경쟁사, 원하는 인상을 뽑는다. 그리고 톤 형용사 세 개를 정한다. 이게 이종 업계 검색의 열쇠다.

### 2. 리서치 (NDA 없을 때만)

고객사의 현재 사이트랑 경쟁사 팔레트를 실제로 확인한다. 업계에 이미 있는 톤이랑 아직 없는 톤을 구분하려고 하는 작업이다.

확인한 것과 새로 제안하는 것을 구분해서 표시한다. 실제로 없는 브랜드 컬러를 있는 것처럼 말하지 않는다.

### 3. 레퍼런스 6칸 수집

`docs/reference-rules.md`의 매트릭스를 전부 채운다. 총 15장(최소 12, 최대 18).

|  | 동종 업계 | 이종 업계 |
|---|---|---|
| 정석 | 3장 | 2장 |
| 변주 | 3장 | 2장 |
| 파격 | 3장 | 2장 |

이종 칸을 비우지 않는다. 동종만 보면 결국 업계 평균이 나온다. 여기가 "생각 못 해봤던 방향"이 나오는 자리다.

이종은 업계명으로 검색하면 안 나온다. 1번에서 뽑은 톤 형용사를 디자인 언어로 바꿔서 찾는다 (`docs/reference-rules.md`).

한 장이 통과하는 조건 다섯 개를 다 만족해야 한다. 특히 이 둘은 반드시 지킨다.
- URL을 직접 열어서 확인한다. WebFetch로 접근해 실재를 확인하고, 안 열리면 버린다. 추측한 주소를 적지 않는다.
- 각 장에 `왜 맞는가` `가져올 것` `버릴 것`을 붙인다. 셋 중 하나라도 못 쓰면 그 레퍼런스는 버린다.

출처 등급은 `docs/reference-rules.md`를 따른다. 실제 운영 사이트 60% 이상, 컨셉 샷 30% 이하. 수집을 마치면 실제 비율을 계산해서 `02-design-style.md`에 적는다.

### 4. 갤러리

이미지가 실제로 보이는 HTML을 만든다. 링크 목록은 산출물이 아니다.

- `projects/[프로젝트명]/drafts/reference-gallery.html`에 저장
- 이미지는 다운로드해서 base64 data URI로 직접 넣는다. 외부 URL로 걸어두면 나중에 열었을 때 깨진다
- 6칸 구조 그대로 섹션을 나눈다. 카드마다 이미지, 출처 링크, 왜 맞는지, 가져올 것, 버릴 것
- 다운로드가 막힌 항목은 우회하지 않는다. 그 항목만 링크랑 설명으로 대체하고 갤러리에 그렇게 표시한다
- 파일을 만든 뒤 실제로 생겼는지 확인하고 절대경로를 알려준다. macOS면 `open`으로 열어준다
- 이 세션에 Artifact 툴이 있으면 Artifact로도 발행해서 링크를 준다. 발행 전에 `artifact-design` 스킬을 읽는다

### 5. 스타일 3방향

`docs/01-stage-analysis.md` 1-3의 항목을 그대로 채운다. `리스크` 칸을 비우지 않는다.

세 방향이 확실히 달라야 한다. 색만 바꾼 변형 셋은 사실상 한 방향이다.

컬러 팔레트를 만들 때 `dataviz` 스킬의 색상 원칙을 참고해도 된다. 다만 대비 실측은 2-0(`ui-tokens`)에서 한다. 여기서 대비 수치를 단정하지 않는다.

### 6. 보여주고 고르게 하기

3방향을 비교표로 보여주고 하나를 추천한다. 갤러리 파일 경로(또는 Artifact 링크)를 같이 준다.

저작권 고지를 한 줄 붙인다. "수집 이미지는 팀 내부에서 방향 잡을 때 보는 용도입니다. 고객사 산출물에 그대로 넣지 않습니다."

사용자가 고르면 `02-design-style.md`의 `확정` 표를 채운다. 두 방향을 섞자고 하면 조합안도 만든다.

### 7. 다음으로

"토큰 확정(2-0)으로 넘어갈까요?" 하고 묻는다. 동의하면 `ui-tokens`를 부른다.

구조랑 스타일이 둘 다 확정되기 전에는 `ui-draft`로 넘어가지 않는다.

## 주의

- 레퍼런스가 안 모인다고 기준을 낮추지 않는다. 12장을 못 채우면 그 사실이랑 이유를 사용자에게 말한다.
- `docs/reference-rules.md`랑 이 파일이 다르면 `docs/reference-rules.md`를 따른다.
