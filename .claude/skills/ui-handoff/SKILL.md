# 3-1 · 정리  (10/31 작성 예정)

이 스킬은 아직 완성되지 않았다. 10월 31일 제출 범위(인계·검수 3과업)다.

호출되면 먼저 사용자에게 알린다.

> "3-1 정리 스킬은 10월 31일에 작성할 예정입니다. 지금은 두 가지만 됩니다. 진행할까요?
>  · 편집 조건 여섯 개 점검 (`04-draft-log.md` 기준)
>  · 토큰 문서 완성도 점검 (`03-design-tokens.md` 기준)"

## 지금 할 수 있는 것

사용자가 동의하면 이 둘만 한다. 둘 다 10/31 작업을 미리 준비하는 성격이다.

**1. 편집 조건 점검**
Figma 파일을 읽어서 `docs/quality-bar.md`의 F 구간을 본다. 여기서 통과해 두면 컴포넌트 정리가 거의 자동으로 끝난다.
복사 붙여넣기한 그룹, 오토레이아웃 없는 프레임, 직접 입력한 색상, `Rectangle 42` 같은 이름, 프레임 이름 규칙을 확인한다.

**2. 토큰 문서 완성도 점검**
`03-design-tokens.md`의 빈칸이랑 대비 검사 안 한 항목을 찾아 목록으로 준다. 스타일가이드는 이 파일을 출력하는 작업이라 이게 부실하면 그때 가서 처음부터 쓰게 된다.

## 하지 않는 것

- 스타일가이드 생성. 출력 형식이랑 목차가 10/31에 정할 항목이다
- 산출물 폴더 구조를 임의로 만드는 것
- `07-handoff.md`의 `[10/31 확정]` 칸을 추측으로 채우는 것
- 조직 라이브러리에 컴포넌트를 올리는 것. 기준이랑 절차가 아직 없다

## 10/31까지 정할 것

`docs/03-stage-wrapup.md`에 네 개 소단계(a 검수 / b 컴포넌트 정리 / c 산출물 정리 / d 스타일가이드)별로 목록이 있다.

## 바뀌지 않는 원리

스타일가이드는 새로 만드는 작업이 아니라 이미 확정된 걸 문서 형태로 출력하는 작업이다. 입력은 `03-design-tokens.md`랑 Figma 컴포넌트다. 앞 단계를 성실히 했으면 이 단계는 짧게 끝난다. 앞을 건너뛰었으면 여기서 프로젝트 전체를 다시 쓰게 된다.
