# 2-3 · 디자인 에셋

상세는 `docs/02-stage-build.md`의 2-3 항목, 프롬프트랑 규격표는 `docs/asset-prompt-library.md`. 둘 다 읽고 시작한다.

입력은 `03-design-tokens.md`랑 `04-draft-log.md`의 에셋 요청 목록. 채우는 파일은 `06-assets.md`.

## 순서

### 1. 목록 만들기

`04-draft-log.md`의 플레이스홀더를 전부 훑어서 `06-assets.md`의 표로 옮긴다. 시안이 아직 없으면 `01-ui-structure.md`의 화면 목록에서 유추하되 `추정` 표시를 한다.

빠뜨리기 쉬운 것들이 있다. OG 이미지, 파비콘, 에러 페이지 일러스트, 빈 상태 일러스트, 로딩 그래픽. 매번 확인한다.

### 2. 어디서 구할지 정하기

이 순서로 판단한다.

| 순위 | 경로 | 언제 |
|---|---|---|
| 1 | 고객사 제공 | 실제 제품, 인물, 공간. 대체 불가 |
| 2 | 직접 제작 | 브랜드 고유 그래픽, 로고 변형, 다이어그램 |
| 3 | 라이선스 스톡 | 일반적인 상황 사진 |
| 4 | AI 생성 | 배경 그래픽, 추상 패턴, 컨셉 이미지, 초안 대체물 |

AI 생성을 1순위로 쓰지 않는다. 사람 얼굴, 실제 제품, 로고, 특정 장소, 텍스트가 들어간 이미지는 AI로 만들지 않는다. 고객사가 반드시 알아본다.

### 3. 고객사 요청 목록

1순위로 분류된 걸 `06-assets.md`의 `고객사 요청 목록` 표로 뽑는다. 이 표를 그대로 복사해서 고객사에 보낼 수 있는 형태로 만든다. 뭘, 어떤 규격으로, 언제까지.

못 받았을 때 어떻게 할지(대체물 사용 / 일정 조정 / 범위 제외)도 미리 적어둔다. 마감 직전에 정하면 늦다.

### 4. 생성 프롬프트

`docs/asset-prompt-library.md`의 여섯 단 구조를 따른다.

```
[1 피사체] [2 구도] [3 스타일] [4 컬러] [5 조명·질감] [6 규격]
```

4번 컬러에 `03-design-tokens.md`의 실제 HEX 값을 그대로 넣는다. "파란색"이라고 쓰면 시안이랑 다른 파란색이 나온다. 프롬프트에서 제일 중요한 항목이다.

텍스트가 올라갈 자리를 구도에 지정한다. `large empty space on the left half` 같은 식으로. 안 하면 매번 다시 만들게 된다.

### 5. 만들고 규격 정리

`docs/asset-prompt-library.md`의 규격 기준표를 적용한다.

```
파일명    [화면ID]_[역할]_[규격].[확장자]
해상도    2배수로
포맷      사진 WebP / 그래픽·아이콘 SVG / 투명 PNG
용량      히어로 300KB · 일반 150KB · 썸네일 60KB · 아이콘 SVG 10KB
```

용량 상한을 넘으면 그 자리에서 압축한다. 개발 인계할 때 반드시 지적받는다.

### 6. 임시 대체물 표시

최종 에셋이 없어서 임시로 만든 건:
- 파일명에 `_TEMP`를 붙인다
- `06-assets.md`의 대체물 목록에 올린다
- 고객사 전달 전에 꼭 교체해야 한다고 사용자에게 알린다

### 7. 기록

AI로 만든 건 도구명, 프롬프트 전문, 생성일, 라이선스 확인 결과를 남긴다. 프롬프트를 요약하지 않는다. 다음에 재현이 안 된다.

### 8. 대체 텍스트

모든 이미지에 alt를 쓴다. 장식용은 빈 값(`alt=""`), 정보 전달용은 이미지가 없을 때 대신 읽힐 문장, 링크 안 이미지는 링크가 어디로 가는지.

"이미지", "사진", 파일명 그대로는 쓰지 않는다.

## 주의

- 에셋이 시안보다 늦게 오면 안 된다. 고객사 요청 목록은 시안 제작이랑 동시에 보낸다.
- 스톡 이미지 라이선스 범위(웹 전용 / 인쇄 포함 / 재판매)를 확인하고 기록한다.
- AI 생성물 라이선스 조건은 도구마다 다르다. 상업적 사용이 되는지 확인하고 기록한다.
