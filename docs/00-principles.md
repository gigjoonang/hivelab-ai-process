# 원칙 — AI를 어디까지 쓰나

프로젝트 사정 따라 바뀌지 않는 것들입니다. 여기랑 다른 얘기가 스킬이나 다른 문서에 적혀 있으면 이 문서를 따릅니다.

---

## 대전제

프로세스를 바꾸지 않습니다. 기존 프로세스 밑에 AI 레이어를 깝니다.

디자이너가 일하는 순서, 산출물 종류, 고객 커뮤니케이션 방식은 그대로입니다. 단계마다 드는 원가와 시간만 바뀝니다.

이건 양쪽으로 적용됩니다. AI가 빨라졌다고 단계를 건너뛰지 않고, AI가 못 하는 구간을 억지로 맡기지도 않습니다.

---

## A급 시안과 B급 시안

이 구분이 프로세스 전체의 중심입니다.

| | A급 시안 | B급 시안 |
|---|---|---|
| 목적 | 고객 제안의 메인 안 | 비교해 보라고 같이 내는 안 |
| 들어가는 것 | 브랜드 해석, 차별화 포인트 | 다른 선택지의 형태 |
| 만드는 사람 | 디자이너가 직접 | AI가 만들고 사람이 고르고 손봄 |
| AI의 역할 | 에셋 생성 보조만 | 제작 전체 |
| 고객 전달 | 그대로 나감 | 그대로 나가지 않음 |
| 품질 책임 | 디자이너 | 디자이너 (고르고 손본 결과에 대해) |

### 흔한 오해

B급이 A급을 대충 만든 버전은 아닙니다. 원래 시간이 없어서 못 만들고 버렸던 안이에요.

지금까지는 3안 제안하면 제작비가 3배였습니다. 그래서 대부분 1안만 제대로 만들고 나머지는 구색이거나, 아예 안 만들었죠. A급/B급을 나누면 그 등식이 깨집니다. 품질을 낮추자는 게 아니라 볼 수 있는 선택지를 늘리자는 쪽입니다.

고객에게 나가는 완성도는 지금까지랑 똑같이 디자이너가 책임집니다.

### B급을 고객에게 보여줄 때

1. [quality-bar.md](quality-bar.md) 통과한 것만
2. 사람이 손본 다음에
3. A급이랑 나란히 놓고, 어느 쪽이 메인 제안인지 밝히고
4. AI로 만들었다는 걸 숨기지 않되 먼저 꺼내지도 않습니다. 도구 얘기가 나오는 순간 디자인 얘기가 사라지거든요. 물어보면 사실대로 답합니다.

---

## AI가 아직 못 들어간 구간

숨기면 나중에 기대치가 어긋나니까 그냥 적어둡니다.

**A급 시안 제작.** 브랜드 해석과 차별화는 아직 사람 영역입니다. 일부러 남겨둔 구간이에요.

**디자인 디벨롭.** 확정안으로 전 화면 만드는 구간인데, 전체 일정에서 제일 큰 덩어리인데도 아직 손을 못 댔습니다. 다음 과제입니다.

이 두 군데에 AI를 억지로 밀어 넣지 마세요. 지금 도구 수준으로는 검수하는 시간이 그냥 만드는 시간보다 깁니다.

---

## 사람이 하는 판단

이건 AI한테 안 넘깁니다. 넘기면 프로세스를 돌리는 의미가 없어집니다.

- **방향 결정** — 3안 중 뭘로 갈지 (1-4)
- **고객에게 나갈 것 고르기** — 어느 시안을, 어느 완성도로
- **브랜드 해석** — 이 브랜드가 뭐여야 하는지
- **품질 합격 판정** — 체크리스트는 아래쪽 선일 뿐입니다
- **저작권·보안 판단** — 이 자료를 써도 되는지, 밖으로 내보내도 되는지

---

## 기록

왜 그걸 골랐는지 안 적어두면 두 달 뒤에 아무도 기억 못 합니다.

각 템플릿에 `결정 기록` 칸이 있습니다. 세 가지를 씁니다.

```
뭘 골랐나  /  왜 골랐나 (근거 하나 이상)  /  뭘 버렸나 (버린 이유)
```

버린 안을 적는 게 특히 중요합니다. 두 달 뒤에 고객이 "그 방향은 왜 안 했어요?" 하고 물을 때, 그리고 다음 프로젝트에서 비슷한 상황을 만날 때 씁니다.

지금까지 이건 개인의 경험이랑 감이었고, 그 사람이 나가면 같이 사라졌습니다. 조직에 남기는 방법이 이 칸입니다.

## 저작권

- 수집한 레퍼런스 이미지의 저작권은 원 출처(디자이너, 스튜디오)에 있습니다.
- 레퍼런스 갤러리는 팀 내부에서 방향 잡을 때 보는 용도입니다. 비공개거나 로컬 파일로만 만듭니다.
- 수집한 이미지를 고객사 제안서나 최종 산출물, 공개 포트폴리오에 그대로 넣지 않습니다.
- 레퍼런스에서 가져오는 건 구성 방식이나 여백 운용 같은 원리지, 그 화면 자체가 아닙니다.
- AI로 만든 이미지는 프롬프트랑 도구명을 `06-assets.md`에 적어둡니다. 고객사가 나중에 물어볼 수 있고, 라이선스 조건도 도구마다 다릅니다.
- 폰트 라이선스는 꼭 확인하세요. 웹 전용인지, 앱까지 포함인지, 임베딩이 되는지가 계약마다 다릅니다. 확인한 결과는 `03-design-tokens.md`에 적습니다.

## 보안

- 고객사 기획 문서, 내부 자료, 아직 공개 안 된 브랜드 자산은 승인된 AI 도구 밖으로 안 나갑니다. 승인 목록은 회사 정책을 따릅니다.
- NDA 있는 프로젝트는 착수할 때 `00-brief.md` 상단에 `NDA: 있음`으로 표시하고, 그 프로젝트에서는 고객사명으로 웹 검색을 하지 않습니다.
- 레퍼런스 검색은 산업군이랑 톤 키워드로만 합니다. 고객사명에 미공개 프로젝트명 붙여서 검색창에 넣지 마세요.
- `projects/` 폴더에는 고객사 자료가 들어갑니다. 외부 저장소에 공개로 올리지 않습니다.

## AI 말을 그대로 믿으면 안 되는 것

아래 항목들은 AI가 자신 있게 틀립니다. 매번 사람이 확인하세요.

| 항목 | 왜 틀리나 | 확인 방법 |
|---|---|---|
| 고객사 기존 브랜드 컬러 | 검색 결과랑 실제가 다를 수 있음 | 고객사 제공 자료 원본 대조 |
| 레퍼런스 URL | 없는 주소를 그럴듯하게 만들어냄 | 전부 직접 열어보기 |
| 색상 대비 수치 | 계산 안 하고 감으로 말함 | 대비 계산기로 실측 |
| 폰트 라이선스 | 조건을 낙관적으로 기억함 | 제작사 공식 페이지 확인 |
| 기획서에 없는 요구사항 | 업계 관행을 문서 내용인 것처럼 말함 | 문서 원문 다시 보기 |

스킬 결과물에 `문서에 없음 — 추정`이 붙어 있으면 그건 아직 가설입니다. 고객 확인 전엔 확정하지 마세요.

## 이 문서를 고칠 때

고정이긴 한데 영구불변은 아닙니다. 고칠 땐 이렇게 합니다.

1. 어떤 프로젝트에서 무슨 문제가 있었는지 근거를 남기고
2. 관련 스킬의 `SKILL.md`도 같이 봅니다. 단, 기준을 스킬로 복사하지 말고 이 문서를 가리키게 두세요
3. 고쳤으면 팀에 알립니다

기준이 스킬마다 복사돼 있으면 언젠가 서로 충돌합니다. 기준은 여기 한 곳에만 둡니다.
