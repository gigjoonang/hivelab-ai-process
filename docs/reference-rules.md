# 레퍼런스 수집 규칙

많이 모으는 게 목적이 아닙니다. 이 프로젝트에 왜 맞는지 설명할 수 있는 것만 모읍니다. 근거를 못 대는 레퍼런스는 회의 시간만 늘립니다. 그런 건 한 장도 넣지 마세요.

---

## 레퍼런스 15장 구성

두 가지 기준을 섞어서 여섯 칸을 만듭니다.

- **얼마나 과감한가**: 정석 / 변주 / 파격, 세 단계
- **어디서 가져왔나**: 같은 업계 / 다른 업계, 두 곳

|  | 같은 업계에서 | 다른 업계에서 |
|---|---|---|
| **정석** · 무난하게 | 3장 | 2장 |
| **변주** · 한 군데만 비틀어서 | 3장 | 2장 |
| **파격** · 확 다르게 | 3장 | 2장 |

총 15장입니다. 최소 12장, 최대 18장. 더 늘리면 고르는 시간만 길어집니다. 여섯 칸 중 하나라도 비우지 마세요.

---

## 과감한 정도: 세 단계

### 정석: 무난하게
업계에서 다들 쓰는 방식 안에서 완성도로 승부하는 안입니다.

같은 업계 상위 사이트와 나란히 놔도 어색하지 않으면 정석입니다. 승인이 빠르고 리스크가 적습니다.

### 변주: 한 군데만 비틀어서
전체 구조는 익숙하게 두고 한 가지 요소만 크게 바꾸는 안입니다. 타이포든 컬러든 모션이든 하나만요.

구조는 익숙한데 어느 한 군데가 확 튀면 변주입니다. 차별화와 안전이 겹치는 자리라 실무에서 제일 많이 채택됩니다.

### 파격: 확 다르게
그 업계에서 아무도 안 쓰는 방식을 가져오는 안입니다.

업계를 모르는 사람에게 보여줬을 때 무슨 업종인지 못 맞히면 파격입니다. 고객의 기대치를 다시 세팅하는 역할을 합니다. 떨어지더라도 나머지 두 안이 상대적으로 좋아 보이게 만듭니다.

> 세 단계를 A·B·C로 부르지 마세요. A급 시안 / B급 시안과 헷갈려서 회의에서 한 번은 꼭 엉킵니다.

---

## 가져오는 곳: 두 가지

### 같은 업계
고객사와 같은 산업군의 사이트입니다. "이 업계에서 이미 이렇게 하고 있다"는 근거가 되기 때문에 고객 설득에 바로 씁니다.

### 다른 업계
전혀 상관없는 산업군에서 **디자인 처리만** 빌려옵니다. 업종을 따라오는 게 아니라 만듦새를 따라오는 겁니다.

금융 서비스인데 스포츠 브랜드의 에너지를 가져온다든가, B2B 소프트웨어인데 잡지의 제목 크기 대비를 가져온다든가 하는 식입니다.

**이 칸을 비우지 마세요.** 같은 업계만 들여다보면 결국 그 업계 평균이 나옵니다. "이런 것도 되는구나" 싶은 방향은 전부 이 칸에서 나옵니다.

## 출처별 우선순위

스킬마다 기준이 달랐는데 이 문서로 통일합니다.

### 1순위: 실제로 운영 중인 사이트 (전체의 60% 이상)

지금 열리고, 실제 사용자가 쓰고 있고, 진짜 콘텐츠 분량을 감당하고 있는 화면입니다.

- 고객사의 실제 경쟁사 사이트: 제일 강한 근거입니다
- Awwwards, Land-book, SiteInspire, Godly, Httpster, One Page Love
- Mobbin: 앱과 웹의 실제 화면 패턴
- 고객사가 직접 언급한 사이트

레이아웃이나 정보 밀도, 메뉴 구성은 **실제 콘텐츠가 들어갔을 때 안 무너지느냐**가 전부입니다. 그건 운영 중인 사이트만 증명해 줍니다.

### 2순위: 만들어만 본 컨셉 이미지 (최대 30%)

Dribbble, Behance, Pinterest에 올라오는 이미지들입니다.

그래픽 처리나 글꼴 조합, 컬러 조합, 일러스트 톤처럼 **겉모습 아이디어**를 볼 때만 씁니다. 레이아웃이나 정보 구조, 메뉴 구성의 근거로는 쓰지 않습니다.

여기 올라온 이미지 상당수는 실제로 만들어진 적이 없습니다. 텍스트 세 줄, 카드 네 장 기준으로 예쁘게 짜여 있어서, 진짜 콘텐츠를 넣으면 무너집니다. 이걸 레이아웃 근거로 쓰면 **예쁘긴 한데 실무에서 못 쓰는 시안**이 나옵니다.

### 3순위: 웹이 아닌 시각 자료 (10% 이내)

잡지 편집, 패키지, 공간, 모션 그래픽 같은 것들입니다. 다른 업계 × 파격 칸에서만 씁니다.

### 쓰지 않는 것

- 원래 어디서 나온 건지 못 찾는 이미지. 핀터레스트에 재업로드된 것 같은 경우
- AI로 만든 목업. 실제 디자인 결정을 거친 물건이 아닙니다
- 5년 넘은 화면. 고전으로 일부러 인용하는 경우는 예외
- 산업군이나 회사 규모가 두 단계 이상 차이 나는 사례. 스타트업 프로젝트에 글로벌 대기업 사례만 모으는 식

## 한 장의 통과 조건

다섯 개를 다 만족해야 합니다. 네 개면 버립니다.

1. **주소가 실제로 열린다.** 추측해서 적지 마세요. 직접 열어보고 확인합니다.
2. **이미지가 실제로 보인다.** 링크만 나열하는 건 수집이 아닙니다.
3. **왜 이 프로젝트에 맞는지 한 문장으로 말할 수 있다.** 기획서의 어느 대목과 연결되는지 적습니다.
4. **가져올 게 하나 특정된다.** "느낌이 좋다"는 가져올 게 아닙니다. "히어로에서 본문으로 넘어갈 때 여백이 몇 배로 벌어지는지" 정도는 돼야 합니다.
5. **버릴 게 하나 특정된다.** 통째로 좋은 레퍼런스는 없습니다. 뭘 안 가져올지 적어야 팀이 오해하지 않습니다.

### 적는 형식

```markdown
**[정석 · 같은 업계] 사이트명**
- 주소: https://...  (확인일 2026-09-17)
- 왜 맞는가: 기획서의 "신뢰감 있는 전문성" 요구와 직결. 같은 B2B 서비스 구조.
- 가져올 것: 헤더 아래 첫 화면을 카피 세 줄로만 채우는 절제
- 버릴 것: 파란색 계열 팔레트. 경쟁사와 겹침
```

## 검색 방법

### 같은 업계

```
site:awwwards.com [산업군]
[산업군] website 2026 site:land-book.com
[경쟁사명] 리뉴얼
[산업군] [정석: best practice / 변주: unconventional / 파격: experimental] web design
```

### 다른 업계

업계 이름으로 검색하면 당연히 같은 업계만 나옵니다. **업계를 빼고 형용사로 찾으세요.**

1. 기획서에서 분위기를 나타내는 형용사 세 개를 뽑습니다: 신뢰감 있는 / 빠른 / 전문적인
2. 그 형용사를 눈에 보이는 특징으로 바꿉니다: 신뢰감 있는 → 여백이 크고 대비가 낮은, 빠른 → 정보가 빽빽하고 모션이 짧은
3. 업계 이름은 빼고 그 특징으로만 검색합니다

```
minimal high-contrast editorial layout
dense data-first interface design
oversized typography landing page
```

### NDA가 있는 프로젝트

고객사 이름으로 검색하지 않습니다. 산업군과 분위기 키워드로만 찾으세요. [00-principles.md](00-principles.md)의 보안 항목을 보세요.

## 갤러리 만들기

수집 결과는 **이미지가 눈에 보이는 형태**로 넘깁니다. 링크 목록은 산출물이 아닙니다.

- 파일명은 `reference-gallery.html`, 프로젝트 폴더 안에 저장
- 이미지는 다운로드해서 HTML 안에 직접 넣습니다. 외부 주소로 걸어두면 나중에 열었을 때 깨집니다
- 여섯 칸 구조 그대로 섹션을 나눕니다. 카드마다 이미지, 출처, 왜 맞는지, 가져올 것, 버릴 것
- 다운로드가 막힌 항목은 억지로 우회하지 말고 링크와 설명으로 대체하고, 갤러리에 그렇게 표시합니다

## 스타일과 레이아웃 분리

섞으면 논의가 엉킵니다.

- **스타일**: 컬러, 글꼴, 그래픽 처리, 사진 톤 → `02-design-style.md`
- **레이아웃**: 화면 구성, 섹션 순서, 그리드, 정보 밀도 → `01-ui-structure.md`

레이아웃도 정석·변주·파격 세 단계로 뽑습니다. 다만 레이아웃은 **다른 업계 칸이 필수가 아닙니다.** 레이아웃은 업계보다 콘텐츠 종류를 따라가거든요. 상품 목록을 다루는 화면은 업계가 달라도 구성이 비슷합니다. 그래서 업계 대신 **콘텐츠 종류가 같은 곳**에서 찾습니다.
