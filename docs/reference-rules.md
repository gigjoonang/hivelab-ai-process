# 레퍼런스 수집 규칙

많이 모으는 게 목적이 아닙니다. 이 프로젝트에 왜 맞는지 설명할 수 있는 것만 모읍니다. 근거를 못 대는 레퍼런스는 회의 시간만 늘립니다. 그런 건 한 장도 넣지 마세요.

---

## 6칸 매트릭스

프로젝트마다 이 여섯 칸을 채웁니다. 칸을 비우지도, 늘리지도 않습니다.

|  | **동종 업계** | **이종 업계** |
|---|---|---|
| **정석** | 3장 | 2장 |
| **변주** | 3장 | 2장 |
| **파격** | 3장 | 2장 |

총 15장입니다. 최소 12장, 최대 18장. 더 늘리면 고르는 시간만 길어집니다.

### 세로축 — 얼마나 대담한가

| 등급 | 어떤 건가 | 어떻게 판별하나 | 왜 필요한가 |
|---|---|---|---|
| **정석** | 업계 문법 안에서 완성도로 승부 | 같은 업계 상위 사이트랑 나란히 놔도 어색하지 않음 | 승인이 빠르고 리스크가 적음 |
| **변주** | 구조는 두고 한 요소만 크게 비틈 | 구조는 익숙한데 타이포·컬러·모션 중 하나가 확 튐 | 차별화랑 안전이 겹치는 자리. 실무에서 제일 많이 채택됨 |
| **파격** | 업계에서 아무도 안 쓰는 문법 | 업계 모르는 사람한테 보여주면 무슨 업종인지 못 맞힘 | 고객 기대치를 다시 세팅함. 떨어져도 나머지 두 안이 좋아 보임 |

등급 이름에 A·B·C를 쓰지 마세요. A급 시안 / B급 시안이랑 헷갈립니다. 회의에서 한 번은 꼭 엉킵니다.

### 가로축 — 어디서 가져오나

**동종 업계** — 같은 산업군. 이 업계에서 이미 통하고 있다는 근거라 고객 설득에 바로 씁니다.

**이종 업계** — 다른 산업군에서 디자인 처리만 빌려옵니다. 금융 서비스에 스포츠 브랜드의 에너지를, B2B SaaS에 매거진의 타이포 위계를 가져오는 식이죠.

이종 칸을 비우지 마세요. 동종만 보면 결국 업계 평균이 나옵니다. 여기가 "생각 못 해봤던 방향"이 나오는 자리입니다.

## 어디서 가져올 것인가

스킬마다 기준이 달랐는데 이 문서로 통일합니다.

### 1순위 — 실제 운영 중인 사이트 (60% 이상)

실제로 열리고, 실제 사용자가 쓰고, 실제 콘텐츠 분량을 감당하고 있는 화면.

- 고객사의 실제 경쟁사 사이트 (제일 강한 근거)
- Awwwards, Land-book, SiteInspire, Godly, Httpster, One Page Love
- Mobbin (앱·웹 실제 화면 패턴)
- 고객사가 직접 언급한 사이트

레이아웃이나 정보 밀도, 내비게이션은 실제 콘텐츠가 들어갔을 때 안 무너지느냐가 전부입니다. 그건 운영 중인 사이트만 증명해 줍니다.

### 2순위 — 컨셉 샷 (최대 30%)

Dribbble, Behance, Pinterest.

그래픽 처리나 타이포 조합, 컬러 조합, 일러스트 톤처럼 **표면 처리 아이디어**를 볼 때만 씁니다. 레이아웃이나 정보 구조, 내비게이션 근거로는 쓰지 않습니다.

이 플랫폼 샷 중에 실제로 구현된 건 얼마 안 됩니다. 텍스트 세 줄, 카드 네 장 기준으로 예쁘게 짜여 있는데 진짜 콘텐츠가 들어가면 무너져요. 이걸 레이아웃 근거로 쓰면 예쁘긴 한데 실무에서 못 쓰는 시안이 나옵니다.

### 3순위 — 업계 밖 시각 자료 (10% 이내)

에디토리얼, 패키지, 공간, 모션 그래픽. 이종 업계 파격 칸에서만 씁니다.

### 안 쓰는 것

- 원 출처를 못 찾는 이미지. 핀터레스트 재업로드본 같은 것
- AI로 만든 목업. 실제 디자인 결정의 근거가 아님
- 5년 넘은 화면. 고전으로 인용하는 경우는 예외
- 산업군이나 규모가 두 단계 이상 차이 나는 사례. 스타트업 프로젝트에 글로벌 대기업 사례만 모으는 식

## 한 장이 통과하려면

다섯 개를 다 만족해야 합니다. 네 개면 버립니다.

1. **URL이 실제로 열린다.** 추측한 주소 적지 마세요. 열어보고 확인합니다. 안 열리면 버립니다.
2. **이미지가 실제로 보인다.** 링크만 나열하는 건 수집이 아닙니다.
3. **왜 이 프로젝트에 맞는지 한 문장으로 말할 수 있다.** 기획서 어느 대목이랑 연결되는지 적습니다.
4. **가져올 게 하나 특정된다.** "느낌이 좋다"는 가져올 게 아닙니다. "히어로에서 본문으로 넘어갈 때 여백이 몇 배로 벌어지는지", "숫자를 본문의 네 배 크기로 쓰는 처리" 정도는 돼야 합니다.
5. **버릴 게 하나 특정된다.** 통째로 좋은 레퍼런스는 없습니다. 뭘 안 가져올지 적어야 팀이 오해를 안 합니다.

### 적는 형식

```markdown
**[정석 · 동종] 사이트명**
- URL: https://... (확인일 2026-09-16)
- 왜 맞는가: 기획서의 "신뢰감 있는 전문성" 요구랑 직결. 같은 B2B 서비스 구조.
- 가져올 것: 헤더 아래 첫 화면을 카피 세 줄로만 채우는 절제
- 버릴 것: 파란색 계열 팔레트. 경쟁사랑 겹침
```

## 어떻게 찾나

### 동종 업계
```
site:awwwards.com [산업군]
[산업군] website 2026 site:land-book.com
[경쟁사명] 리뉴얼
[산업군] [정석: best practice / 변주: unconventional / 파격: experimental] web design
```

### 이종 업계

동종 검색으로는 안 나옵니다. 형용사로 찾으세요.

1. 기획서에서 톤 형용사 세 개를 뽑습니다 (신뢰감 있는 / 빠른 / 전문적인)
2. 그걸 디자인 언어로 바꿉니다 (신뢰감 → 여백이 크고 대비가 낮은 / 빠른 → 정보 밀도가 높고 모션이 짧은)
3. 업계를 빼고 그 언어로만 검색합니다

```
minimal high-contrast editorial layout
dense data-first interface design
oversized typography landing page
```

### NDA 프로젝트면

고객사명으로 검색하지 않습니다. 산업군이랑 톤 키워드로만 찾으세요. [00-principles.md](00-principles.md)의 보안 항목을 보세요.

## 갤러리

수집 결과는 이미지가 눈에 보이는 형태로 전달합니다. 링크 목록은 산출물이 아닙니다.

- 파일명은 `reference-gallery.html`, 프로젝트 폴더 안에 저장
- 이미지는 base64 data URI로 HTML에 직접 넣습니다. 외부 URL로 걸어두면 나중에 열었을 때 깨져요
- 6칸 구조 그대로 섹션을 나눕니다. 카드마다 이미지, 출처 링크, 왜 맞는지, 가져올 것, 버릴 것
- 다운로드가 막힌 항목은 우회하지 말고, 그 항목만 링크랑 설명으로 대체하고 갤러리에 그렇게 표시합니다

## 스타일이랑 레이아웃은 따로 모읍니다

섞으면 논의가 엉킵니다.

- **스타일** — 컬러, 타이포, 그래픽 처리, 사진 톤 → `02-design-style.md`
- **레이아웃** — 화면 구성, 존 순서, 그리드, 정보 밀도 → `01-ui-structure.md`

레이아웃도 정석·변주·파격으로 뽑습니다. 다만 레이아웃은 이종 업계 칸이 필수는 아닙니다. 레이아웃 문법은 업계보다 콘텐츠 유형을 따라가거든요. 대신 콘텐츠 유형이 같은 다른 업계에서 찾습니다. 상품 목록 구조를 가진 업계는 다 비슷한 식으로요.
