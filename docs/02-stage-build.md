## 2-0 · 디자인 토큰

스킬 `/ui-tokens` · 채우는 파일 `03-design-tokens.md`

### 순서를 바꾼 이유

지금까지는 화면 다 그리고 나서 디자인 시스템을 정리했습니다. 그건 전 화면을 다시 만지는 일이에요. 시안 전에 정해두면 한 번만 정하면 됩니다.

이 프로세스에서 기존이랑 순서가 달라지는 건 여기 하나뿐입니다. 나머지는 그대로예요.

### 정하는 것

**컬러.** 값까지 정합니다. "파란색 계열"은 토큰이 아닙니다.
```
Primary     기본 / hover / active / 비활성  (4단)
Secondary   기본 / hover                    (2단)
Accent      기본                            (1단)
Neutral     0 · 50 · 100 · 200 · 400 · 600 · 800 · 900  (8단)
Semantic    success / warning / error / info (각각 배경·전경 2단)
```
Neutral 8단이 많아 보여도 줄이지 마세요. 배경, 구분선, 보조텍스트, 본문, 제목이 다 다른 단이 필요합니다. 부족하면 시안에서 임의 색이 생겨요.

**타이포.** 국문 기준으로 정하고 영문을 맞춥니다. 반대로 하면 국문이 깨집니다.
```
Display / H1 / H2 / H3 / Body-L / Body / Body-S / Caption / Label
각 항목: 폰트 · 크기 · 굵기 · 행간 · 자간
```
- 국문 자간은 -1% ~ -3% 사이에서, 크기가 클수록 좁힙니다
- 행간은 본문 1.6~1.75, 제목 1.2~1.35
- 웹폰트 라이선스 확인 결과를 이 파일에 적어두세요. 웹 전용인지, 앱 포함인지, 임베딩이 되는지

**간격.** 4 또는 8 배수 하나로 통일합니다.
`4 · 8 · 12 · 16 · 24 · 32 · 48 · 64 · 96 · 128`

**반경, 그림자, 테두리.** 각각 3단 이내로. 많으면 일관성이 사라집니다.

**그리드와 브레이크포인트.** `01-ui-structure.md`에서 정한 값을 그대로 옮깁니다. 여기서 새로 정하지 않습니다.

### 꼭 하는 검사

| 검사 | 기준 | 방법 |
|---|---|---|
| 본문 텍스트 대비 | 4.5:1 이상 | 대비 계산기로 실측 |
| 큰 텍스트 (18.66px+ Bold 또는 24px+) | 3:1 이상 | 실측 |
| UI 요소 경계, 아이콘 | 3:1 이상 | 실측 |
| Primary 위의 흰 텍스트 | 4.5:1 이상 | 실측 |
| 비활성 상태 | 구분은 되게, 대비 기준은 예외 | 눈으로 확인 |

AI가 말한 대비 수치는 믿지 마세요. 계산 없이 감으로 답합니다. 꼭 실측하세요. [00-principles.md](00-principles.md)에 관련 항목이 있습니다.

### 고객사에 기존 시스템이 있으면

새로 만들지 않습니다. 기존 토큰을 그대로 받아 적고, 이 프로젝트에서 추가로 필요한 것만 `신규` 표시로 붙입니다. 신규 항목은 고객사 시스템 담당자한테 확인받으세요.

### 종료 기준
토큰 표 완성, 대비 검사 전 항목 통과, 폰트 라이선스 확인 완료.

## 2-1 · 시안

스킬 `/ui-draft` · 채우는 파일 `04-draft-log.md`

네 단계로 나뉩니다. 건너뛰지 마세요.

### a. 디자인 컨셉

컨셉은 한 문장입니다. 형용사가 두 개 이상 들어가면 컨셉이 아니라 희망사항이에요.

```
[대상]에게 [무엇]을 [어떤 방식]으로 보여주는 화면
```

컨셉이 정해지면 거기서 디자인 규칙 세 개를 뽑습니다. 시안 만들다 판단이 갈릴 때 쓰는 기준입니다.

```
컨셉이 "정보를 숨기지 않는다"라면
  규칙 1: 아코디언이나 탭으로 콘텐츠를 접지 않는다
  규칙 2: 한 화면에서 스크롤로 전체를 볼 수 있게 한다
  규칙 3: 강조는 크기가 아니라 위치로 한다
```

### b. 컴포넌트 설계

나중에 편집이 편한 시안이 되느냐가 여기서 갈립니다. 화면 먼저 그리고 나중에 컴포넌트로 묶으면 안 묶이는 조각이 꼭 남아요.

`01-ui-structure.md`의 화면 목록을 훑어서 두 번 이상 반복되는 요소를 전부 후보로 올립니다.

거의 모든 프로젝트에 필요한 것들:
```
Button        variant: primary·secondary·ghost / size: L·M·S / state: default·hover·pressed·disabled
Input         state: default·focus·error·disabled / with-label · with-helper
Card          variant: 기본·이미지상단·가로형
Badge / Tag
Header (desktop · mobile)
Footer
Nav Item      state: default·hover·active
Modal / Toast
Icon          단일 컴포넌트 + variant로 아이콘 교체
```

프로젝트별로 더 필요한 건 화면 목록에서 뽑습니다.

명명이랑 구조 규칙은 [design-system-rules.md](design-system-rules.md)를 따릅니다. 여기서 새로 정하지 않습니다.

### c. HTML 시안 먼저

Figma에 바로 그리지 않습니다. HTML/CSS로 먼저 만들어요.

Figma를 자동으로 조작하는 도구는 사각형, 텍스트, 단색 채우기 정도밖에 못 합니다. 말로 된 설명만 보고 좌표를 추측해서 그리면 엉성하게 나와요. HTML/CSS로 타이포랑 여백, 대비를 제대로 잡은 화면을 먼저 만들어놓고 그걸 보면서 옮기면 훨씬 정확합니다.

- `03-design-tokens.md` 값을 CSS 변수로 선언하고 그것만 씁니다. 색상 하드코딩 금지
- 카피는 기획서에 실제 문구 후보가 있으면 그걸 쓰고, 없으면 무슨 역할의 텍스트인지 알 수 있는 자리표시 문구를 씁니다. `Lorem ipsum`은 쓰지 마세요. 국문이랑 길이감이 완전히 달라서 레이아웃 판단이 안 됩니다
- 데스크톱 폭 기준으로 만들고 PNG로 캡처합니다
- 캡처를 먼저 보여주고 확인받습니다

### d. Figma 이관

HTML 캡처를 청사진 삼아 옮깁니다.

1. 기존 파일에 재사용할 로컬 컴포넌트나 텍스트 스타일이 있는지 확인합니다. 있으면 새로 만들지 말고 인스턴스로 배치하세요
2. 토큰을 Figma에 올립니다. 컬러/타이포 스타일이나 변수로 먼저
3. b에서 정한 컴포넌트를 컴포넌트로 먼저 만듭니다
4. 최상위 프레임 생성. 데스크톱 폭, 세로 오토레이아웃
5. 섹션별 하위 프레임을 오토레이아웃으로 만들고 컴포넌트 인스턴스를 배치해서 채웁니다
6. 이미지 자리는 색상 플레이스홀더 사각형에 규격 표기

**인계되려면 이걸 만족해야 합니다**
- [ ] 반복 요소가 전부 컴포넌트 인스턴스다. 복사 붙여넣기한 그룹이 없다
- [ ] 모든 프레임에 오토레이아웃이 걸려 있다
- [ ] 색상이 스타일이나 변수로 연결돼 있다. 직접 입력한 색이 없다
- [ ] 텍스트가 텍스트 스타일로 연결돼 있다
- [ ] 레이어 이름이 역할을 말한다. `Rectangle 42` 같은 게 없다
- [ ] 프레임 이름이 `화면ID_화면명_등급_방향` 형식이다

### 기술적 한계 고지

Figma 자동 조작에는 한계가 있습니다. 결과 공유할 때 아래를 매번 같이 말하세요. 안 말하면 기대치가 어긋납니다.

| 한계 | 실제로 일어나는 일 | 어떻게 하나 |
|---|---|---|
| 폰트 지정 불가 | HTML 시안의 웹폰트가 그대로 안 들어감 | 파일의 기존 텍스트 스타일 중 제일 가까운 걸 고르고, 다르다고 말함 |
| 사진 삽입 불가 | 사진이 색상 사각형으로 대체됨 | 플레이스홀더에 규격 표기. 2-3에서 실제 에셋으로 교체 |
| 그라데이션·그림자 제한 | 단색으로 단순화됨 | HTML 시안 이미지를 같이 전달해서 의도를 남김 |

[quality-bar.md](quality-bar.md) 전 항목 통과, 위 편집 조건 여섯 개 통과, `04-draft-log.md` 기록 완료.

## 2-3 · 디자인 에셋

스킬 `/ui-assets` · 채우는 파일 `06-assets.md`

### 순서

**1. 목록 만들기**
`04-draft-log.md`의 플레이스홀더를 전부 훑어서 표로 만듭니다.
```
| ID | 쓰이는 화면 | 종류 | 규격(px) | 확보 경로 | 상태 |
```
종류는 사진, 일러스트, 아이콘, 그래픽 패턴, 로고 변형, 동영상 썸네일, OG 이미지, 파비콘.

**2. 어디서 구할지 정하기**

| 순위 | 경로 | 언제 |
|---|---|---|
| 1 | 고객사 제공 | 실제 제품, 인물, 공간 사진. 대체 불가 |
| 2 | 직접 제작 | 브랜드 고유 그래픽, 로고 변형, 다이어그램 |
| 3 | 라이선스 스톡 | 일반적인 상황 사진. 고객사가 계정 있으면 그쪽 우선 |
| 4 | AI 생성 | 배경 그래픽, 추상 패턴, 컨셉 이미지, 초안용 대체물 |

AI 생성을 1순위로 쓰지 마세요. 사람 얼굴, 실제 제품, 고객사 공간, 로고는 AI로 만들지 않습니다. 고객사가 반드시 알아봅니다.

**3. 생성 프롬프트 쓰기**
구조랑 예시는 [asset-prompt-library.md](asset-prompt-library.md)에 있습니다. 프로젝트 토큰의 컬러값을 프롬프트에 직접 넣는 게 핵심입니다.

**4. 만들고 규격 정리**
```
파일명   [화면ID]_[역할]_[규격].[확장자]   예: HOME_hero-bg_2880x1620.webp
해상도   2배수로. 배경 이미지는 1920 / 2880 두 벌
포맷     사진 WebP(JPEG는 대체), 그래픽·아이콘 SVG, 투명 필요하면 PNG
용량     히어로 300KB 이하, 일반 이미지 150KB 이하
alt      전 항목 작성. 접근성 요구가 있으면 필수
```

**5. 기록**
AI로 만든 건 도구명, 프롬프트 전문, 생성일을 `06-assets.md`에 남깁니다. 고객사가 나중에 물어볼 수 있고 라이선스 조건도 도구마다 다릅니다.

### 종료 기준
목록 전 항목이 확보 완료거나 고객사 대기 상태, 생성한 건 프롬프트 기록 완료, alt 텍스트 작성 완료.

## 2-5 · 디자인 디벨롭: 사람 구간

확정안으로 전 화면 만드는 구간입니다. 전체 일정에서 제일 큰 덩어리인데 아직 AI가 못 들어갔어요. 다음 과제입니다.

지금 이 구간에서 할 수 있는 건 하나입니다. b단계에서 컴포넌트를 제대로 만들어두면 디벨롭 속도가 올라갑니다.
