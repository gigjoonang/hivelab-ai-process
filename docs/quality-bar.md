# 품질 기준: B급 시안 체크리스트

여기를 다 통과해도 좋은 시안이라는 뜻은 아닙니다. 하나라도 걸리면 내보낼 수 없다는 뜻입니다.

지금까지는 기준이 없어서 각자 눈대중으로 봤습니다. 그러다 보니 누가 만들었느냐에 따라 결과가 달랐고요. 이 목록은 그 편차를 줄이려고 만들었습니다.

`/ui-draft`를 끝낼 때 스스로 점검하고, `/ui-review`가 다시 기계적으로 검사합니다.

---

## A. 토큰 준수

불합격이 제일 많이 나오는 구간입니다.

- [ ] 화면에 쓴 색이 전부 `03-design-tokens.md`에 있다. 화면에서 색을 뽑아 표와 대조했다
- [ ] 폰트 크기를 전부 타입 스케일에서 가져왔다. 17px, 23px처럼 어중간한 값을 쓰지 않았다
- [ ] 간격을 전부 4 또는 8 배수로 맞췄다
- [ ] 반경과 그림자를 정해둔 단계 안에서 골랐다
- [ ] 그리드 칼럼·거터·최대폭을 `01-ui-structure.md` 값 그대로 썼다

토큰을 벗어난 값은 시안에서는 티가 안 납니다. 전 화면에 퍼진 뒤 디벨롭에서 터집니다.

## B. 대비와 접근성

- [ ] 본문 텍스트 대비 4.5:1 이상. 계산기로 직접 쟀다
- [ ] 큰 텍스트(18.66px 이상 Bold 또는 24px 이상) 3:1 이상
- [ ] 버튼과 입력필드 경계, 아이콘 3:1 이상
- [ ] 플레이스홀더 텍스트도 본문 대비 기준을 넘긴다
- [ ] 이미지 위 텍스트에 오버레이나 그림자를 깔았다
- [ ] 정보를 색으로만 구분한 곳에 아이콘이나 텍스트를 같이 넣었다
- [ ] 모바일 터치 타겟을 44×44px 이상으로 잡았다

## C. 상태값

두 번째로 많이 나오는 구간입니다.

- [ ] 버튼 네 종을 그렸다. default / hover / pressed / disabled
- [ ] 입력 네 종에 에러 메시지 자리까지 그렸다. default / focus / error / disabled
- [ ] 링크 세 종을 그렸다. default / hover / visited
- [ ] 목록 화면의 빈 상태를 그렸다
- [ ] 로딩 처리 방식을 정했다. 스켈레톤 / 스피너 / 안 씀
- [ ] 탭과 내비, 체크박스의 선택 상태를 그렸다

## D. 콘텐츠 현실성

- [ ] 카피를 전부 국문으로 채웠다. `Lorem ipsum`을 쓰지 않았다
- [ ] 제일 긴 경우를 넣어봤다. 제목 두 줄, 메뉴명 최장, 가격 여덟 자리, 이름 긴 경우
- [ ] 제일 짧은 경우도 넣어봤다. 항목 하나, 텍스트 한 줄
- [ ] 목록 항목 수를 실제 예상 범위로 채웠다. 카드 세 장만 놓고 판단하지 않았다
- [ ] 이미지 자리에 실제 비율과 규격을 적어뒀다

## E. 구조 일치

- [ ] 존 순서를 `01-ui-structure.md`의 확정 레이아웃 그대로 따랐다
- [ ] 화면 목록에 있는 화면이고 화면 ID를 붙였다
- [ ] 내비게이션 항목을 IA 트리와 맞췄다
- [ ] 데스크톱 말고 브레이크포인트를 최소 하나 더 그렸다

## F. 편집 가능성

Figma 시안만 해당합니다.

- [ ] 반복되는 요소를 전부 컴포넌트로 만들어 배치했다. 복사 붙여넣기한 그룹을 남기지 않았다
- [ ] 모든 프레임에 오토레이아웃을 걸었다
- [ ] 색을 전부 스타일이나 변수로 연결했다. 직접 입력한 색을 남기지 않았다
- [ ] 텍스트를 전부 텍스트 스타일로 연결했다
- [ ] 레이어 이름을 알아볼 수 있게 바꿨다. `Rectangle 42` 같은 걸 남기지 않았다
- [ ] 프레임 이름을 `화면ID_화면명_등급_방향` 형식으로 지었다

## G. 스타일 방향 일치

- [ ] `02-design-style.md`의 확정 방향대로 만들었다
- [ ] 세 방향을 만들었다면 서로 확실히 다르다. 색만 바꾼 건 같은 안으로 친다
- [ ] 2-1-a에서 정한 디자인 규칙 세 개를 지켰다

## H. 전달 전 고지 사항

- [ ] B급 시안이라고 밝혔다
- [ ] 폰트가 의도와 다를 수 있다고 알렸다
- [ ] 사진이 색 플레이스홀더라고 알렸다
- [ ] 어느 구조안에 어느 스타일 방향 조합인지 밝혔다

## 불합격 처리

| 구간 | 어떻게 |
|---|---|
| A 토큰 준수 | 다시 만듭니다. 손으로 고치면 또 생겨요. 토큰 자체가 틀렸으면 2-0으로 |
| B 대비와 접근성 | 2-0으로 갑니다. 시안에서 색을 바꾸면 다른 화면과 어긋납니다 |
| C 상태값 | 해당 컴포넌트만 보강 |
| D 콘텐츠 현실성 | 해당 화면만 다시 |
| E 구조 일치 | 1-2 확정안을 먼저 봅니다. 시안이 틀린 건지 구조안이 틀린 건지 |
| F 편집 가능성 | 해당 화면 다시. 예외 없습니다. 여기서 봐주면 3단계 정리를 못 합니다 |
| G 스타일 방향 일치 | 1-4로 돌아갑니다 |
| H 전달 전 고지 사항 | 전달 전에 문구 추가 |

일정이 급하면 시안 개수를 줄이세요. 기준을 낮추지는 마시고요.
