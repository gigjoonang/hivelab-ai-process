## a. A급·B급 시안 검수

**정해진 것**
- 검수 대상은 고객사에 나가는 모든 시안입니다. A급도 포함이에요. 사람이 만든 것도 같은 기준을 받습니다
- 최소 기준은 [quality-bar.md](quality-bar.md)

**10/31까지 정할 것**
- [ ] A급이랑 B급에 같은 체크리스트를 쓸지, A급 전용 항목을 더할지
- [ ] 검수자가 누구인지. 만든 사람 본인인지, 동료인지, 리드인지
- [ ] 불합격 처리 절차. 반려 기준이랑 재검수 시점
- [ ] 2-2 컨펌이랑 역할 분담. 2-2는 B급만 보고 3-1은 전체를 보는데, 중복을 어떻게 줄일지

## b. 컴포넌트 정리

**정해진 것**
- 정리 대상은 Figma 파일의 컴포넌트 전체
- 명명 규칙은 [design-system-rules.md](design-system-rules.md)

**10/31까지 정할 것**
- [ ] 정리 항목. 미사용 제거, 중복 병합, variant 통합, 이름 정규화, 분리된 인스턴스 복구
- [ ] 자동으로 잡히는 것과 사람이 판단할 것의 경계
- [ ] 정리 결과를 어떤 형식으로 보고할지
- [ ] 재사용 자산 환원 규칙. 이번에 잘 만든 컴포넌트를 조직 라이브러리로 올리는 기준과 절차

## c. 산출물 정리

**정해진 것**
- 산출물은 `projects/[프로젝트명]/` 안에 모입니다

**10/31까지 정할 것**
- [ ] 고객사 전달 산출물 표준 목록. Figma 링크, 스타일가이드, 에셋 패키지, 개발 인계 문서, 원본 파일
- [ ] 폴더 구조랑 파일 명명 규칙
- [ ] 개발 인계 범위. 어디까지가 디자인의 일인지
- [ ] 보관 정책. 어디에, 얼마나, 누가 접근하는지

## d. 스타일가이드 (고객사 납품)

**정해진 것**
- 입력은 `03-design-tokens.md`랑 Figma 컴포넌트입니다. 새로 만드는 게 아니라 이미 확정된 걸 문서 형태로 출력하는 작업이에요

**10/31까지 정할 것**
- [ ] 출력 형식. PDF인지, 웹페이지인지, Figma 페이지인지, 셋 다인지
- [ ] 목차 표준안
- [ ] 자동으로 뽑을 범위랑 사람이 쓸 범위. 토큰 표는 자동, 사용 원칙 문장은 사람
- [ ] 고객사 유형별 분기. 개발팀이 있는 고객사랑 없는 고객사는 필요한 문서가 다릅니다
