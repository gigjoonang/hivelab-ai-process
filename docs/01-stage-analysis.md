# 1단계 · 분석

디자인을 시작해도 되는 상태를 만드는 단계입니다. 정보를 모으는 게 아니라 뭐가 비었는지 확정하는 쪽에 가깝습니다.

나오는 것 — `00-brief.md`, `01-ui-structure.md`, `02-design-style.md` + `reference-gallery.html`

---

## 1-1 · 기획 문서 분석

스킬 `/ui-analyze` · 채우는 파일 `00-brief.md`

### 달라지는 점

기획서를 통독하고 화면 리스트를 손으로 정리하던 일이, 요약본 받아서 검증하는 일로 바뀝니다. 읽기가 검증으로 바뀌는 거지 안 읽어도 된다는 뜻이 아닙니다. AI 요약만 믿고 넘어가면 여기서 프로젝트가 틀어집니다.

### 뽑아내는 여섯 가지

**1. 비즈니스 목표**
이 사이트가 잘됐다는 게 뭘 말하는지 한 문장으로. 브랜딩인지, 리드 확보인지, 판매인지, 정보 제공인지, 예약인지. 문서에 여러 개 적혀 있으면 순위를 매기고, 순위가 문서에 없으면 그게 첫 번째 확인 질문이 됩니다.

**2. 타겟 사용자와 방문 맥락**
누가, 어떤 상황에서, 뭘 알고 들어오는지. 특히 모바일 비중이랑 첫 방문/재방문 비중은 레이아웃을 결정하니까 꼭 확인하세요.

**3. 화면·기능·콘텐츠 목록**
문서에 나열된 메뉴랑 기능을 전부 표로 옮깁니다. 이 개수가 곧 일정입니다.

**4. 제약**
플랫폼, 반응형 범위, 다국어, 접근성 요구 수준, 기존 시스템 연동, 브라우저 지원, 일정, 예산, CMS 여부.

**5. 디자이너가 챙겨야 할 것**
기획서에 적혀는 있는데 읽고 그냥 넘어가기 쉬운 항목들입니다. 아래 표를 매번 훑으세요.

| 체크 | 놓치면 |
|---|---|
| 콘텐츠 분량이 가변인 영역이 있나 | 시안은 예쁜데 실제 데이터 넣으면 무너짐 |
| 로그인 전/후 화면이 나뉘나 | 화면 수가 1.5배로 늘어남 |
| 관리자 화면이 범위에 있나 | 견적 밖의 일이 견적 안으로 들어옴 |
| 다국어가 있나 | 한글 기준으로 잡은 타이포가 영문에서 깨짐 |
| 기존 디자인 시스템이나 브랜드 가이드가 있나 | 토큰 새로 만들었는데 못 씀 |
| 접근성 요구 수준 (공공·금융이면 필수) | 대비랑 포커스를 전면 재작업 |
| 고객사가 콘텐츠를 직접 넣나 (CMS) | 디자이너가 통제 못 하는 조합이 생김 |
| 개발 프레임워크가 정해져 있나 | 구현 못 하는 인터랙션을 제안함 |
| 실제 사진·영상 자산이 있나 | 시안은 스톡인데 실물은 다른 사진 |
| 법적 고지나 약관 화면이 있나 | 마감 직전에 화면이 추가됨 |

**6. 문서에 없는 것**
빠진 정보를 목록으로 만들고, 항목마다 누구한테 언제 물을지 붙입니다.

이 단계에서 제일 값나가는 산출물이 이 질문 목록입니다. 요약은 AI가 알아서 해주니까 시간을 여기 쓰세요. 기획서는 늘 어딘가 비어 있는데, 그걸 시안 만들다가 발견하면 이미 늦습니다.

### 종료 기준

- 전략 한 줄. `이 프로젝트의 디자인은 ○○로 승부한다`
- 리스크 3개. 각각 대응 방안까지
- 고객사에 물어볼 질문 3~7개. 그보다 많으면 기획서가 아직 기획서가 아닙니다
- 기본정보 표에 빈칸 없음

### 자주 나는 사고

**AI 요약만 보고 원문을 안 읽는 것.** 숫자랑 고유명사는 원문이랑 대조하세요.

**추정을 사실로 적는 것.** `문서에 없음 — 추정` 표시가 붙어 있으면 고객 확인 전까진 확정하지 마세요.

**질문 목록 만들어놓고 안 물어보는 것.** 1-4에서 어차피 다시 막힙니다. 이 단계에서 보내세요.

## 1-2 · 구조 · 레이아웃

스킬 `/ui-structure` · 채우는 파일 `01-ui-structure.md`

### 달라지는 점

지금까지는 경험으로 1안 잡고 시작했습니다. 이제는 구조 유형 몇 개를 근거랑 같이 비교하고 고릅니다.

### 순서

**1. 사이트 유형 판단**
랜딩페이지형, 기업소개형, 커머스형, 대시보드·SaaS형, 콘텐츠허브형, 커뮤니티형, 포트폴리오형, 예약·신청형. 기획서가 여러 유형 특성을 섞어서 요구하면 억지로 하나에 끼워 맞추지 말고 하이브리드로 제안하세요.

**2. IA 트리**
3뎁스를 넘기지 않습니다. 넘어가면 그 가지는 별도 섹션으로 분리해야 한다는 뜻입니다.

**3. 화면 목록 표**
```
| 화면 ID | 화면명 | 뎁스 | 유형 | 반응형 | 상태 변형 | 비고 |
```

`상태 변형`은 빈 상태, 로딩, 에러, 권한 없음처럼 추가로 그려야 하는 화면입니다. 이 칸을 채우면 실제 화면 수가 드러납니다. 보통 명목 화면 수의 1.3~1.6배가 나와요. 이 숫자가 일정의 근거가 됩니다.

**4. 메인 레이아웃 3안**

| 등급 | 어떤 건가 |
|---|---|
| **정석** | 그 유형의 표준 존 순서. 헤더 → 히어로 → 핵심가치 → 근거 → CTA → 푸터 |
| **변주** | 존 하나를 크게 재배치. 히어로를 빼고 바로 실제 화면이나 상품을 보여주거나, 좌측 고정 내비 |
| **파격** | 스크롤 문법 자체를 바꿈. 가로 스크롤, 풀스크린 섹션 전환, 단일 캔버스 |

안마다 존 순서랑 그리드(칼럼, 거터, 최대폭), 데스크톱/모바일 기준값을 적습니다. 이 값을 `/ui-draft`가 그대로 받아서 씁니다.

기획서에 다른 값이 없으면 이걸 씁니다.
```
데스크톱 1440, 콘텐츠 최대폭 1200, 12칼럼, 거터 24
태블릿 768, 8칼럼 / 모바일 375, 4칼럼
```

### 종료 기준
화면 목록 표가 확정되고, 레이아웃 3안 중 하나가 골라지고, 왜 골랐는지 적혀 있으면 됩니다.

## 1-3 · 스타일 · 레퍼런스

스킬 `/ui-style` · 채우는 파일 `02-design-style.md` + `reference-gallery.html`

### 달라지는 점

지금까지는 직접 수집하고 조판했습니다. 본 양이 곧 쓴 시간이었죠. 이제 탐색량이 시간에서 분리됩니다. 더 많이 보라는 게 아니라 같은 시간에 더 넓게 보고 고를 수 있다는 뜻입니다.

### 순서

1. `00-brief.md`에서 브랜드 단서 뽑기. 회사명, 산업군, 타겟, 기존 브랜드 자산, 경쟁사, 원하는 인상
2. NDA 없으면 실제로 찾아보기. 고객사 현재 사이트, 경쟁사 팔레트. 업계에 이미 있는 톤이랑 아직 없는 톤을 구분하려고 하는 작업입니다
3. 레퍼런스 6칸 수집. [reference-rules.md](reference-rules.md)를 그대로 적용합니다
4. 갤러리 HTML 만들기
5. 스타일 3방향 뽑기

### 한 방향에 들어가는 것

```markdown
### [등급]: 컨셉명 한 줄
- 키워드: 3~5개
- 컬러: Primary / Secondary / Accent / Neutral 4단 / Semantic(성공·경고·오류)
- 타이포: 헤드라인 서체 성격 + 본문 서체 성격 + 국문/영문 조합
- 그래픽: 사진 톤, 일러스트 유무, 아이콘 스타일(선 굵기·모서리), 모션 성격
- 근거 레퍼런스: 갤러리 어느 칸 몇 번
- 맞는 이유: 기획서 어느 대목이랑 연결되나
- 리스크: 이 방향이 실패한다면 어떤 이유로
```

`리스크` 칸을 비우지 마세요. 세 방향의 리스크를 나란히 놓으면 고객 결정이 빨라집니다.

세 방향은 서로 확실히 달라야 합니다. 색만 바꾼 변형 세 개는 3방향이 아니라 1방향이에요.

### 종료 기준
3방향이 나오고, 갤러리 파일이 실제로 있고, 하나가 골라지고, 이유가 적혀 있으면 됩니다.

## 1-4 · 방향 확정

AI가 아니라 사람이 통과시킵니다.

### 통과 조건

세 문장이 정해져야 합니다.

```
구조     — [유형]으로 간다. 화면 [n]개.
레이아웃 — [정석 / 변주 / 파격]으로 간다.
스타일   — [정석 / 변주 / 파격]으로 간다.
```

정하고 나서 `01-ui-structure.md`랑 `02-design-style.md`의 `확정` 칸에 날짜랑 정한 사람 이름을 적습니다.

### 컨펌이 늦어지는 경우

멈추지 않습니다. 내부 기준안을 먼저 확정하고 진행하되 파일에 `내부 확정 — 고객 대기`로 표시해 두세요. 나중에 고객이 다른 방향을 고르면 [WORKFLOW.md](../WORKFLOW.md)의 되돌아가는 규칙대로 합니다.

### 여기를 건너뛰면

시안 개수만 늘어나고 아무것도 확정이 안 됩니다. 그리고 2단계 전체가 재작업 대상이 됩니다. 형식 때문에 만든 단계가 아니라 여기서 비용이 정해져서 만든 단계예요.
