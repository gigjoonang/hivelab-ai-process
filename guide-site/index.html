PRINCIPLES

원칙: AI 사용 범위

프로젝트 사정 따라 바뀌지 않는 것들입니다. 여기랑 다른 얘기가 다른 데 적혀 있으면 이걸 따릅니다.

대전제

프로세스를 바꾸지 않습니다. 기존 프로세스 밑에 AI 레이어를 깝니다. 디자이너가 일하는 순서, 산출물 종류, 고객 커뮤니케이션 방식은 그대로고 단계마다 드는 원가랑 시간만 바뀝니다.

이건 양쪽으로 적용됩니다. AI가 빨라졌다고 단계를 건너뛰지 않고, AI가 못 하는 구간을 억지로 맡기지도 않습니다.

B급이 A급을 대충 만든 버전은 아닙니다. 원래 시간이 없어서 못 만들고 버렸던 안이에요.

지금까지는 3안 제안하면 제작비가 3배였습니다. 그래서 대부분 1안만 제대로 만들고 나머지는 구색이거나 아예 안 만들었죠. A급/B급을 나누면 그 등식이 깨집니다. 품질을 낮추자는 게 아니라 볼 수 있는 선택지를 늘리자는 쪽입니다.

꼭 지킬 것 네 가지

  1. 고객에게 나가는 완성도는 사람이 책임집니다. AI가 만든 건 검수하고 손보기 전엔 고객사로 안 나갑니다.
  2. 앞 단계 파일이 비어 있으면 다음으로 안 넘어갑니다. 앞이 비면 뒤 단계 AI가 알아서 추측으로 채웁니다.
  3. 왜 골랐는지 적어둡니다. 안 적어두면 두 달 뒤에 아무도 기억 못 해요.
  4. 고객사 자료는 저장소랑 승인된 도구 밖으로 안 나갑니다.

사람이 하는 판단

이건 AI한테 안 넘깁니다. 넘기면 프로세스를 돌리는 의미가 없어집니다.

  • 방향 결정 — 3안 중 뭘로 갈지 (1-4)
  • 고객에게 나갈 것 고르기 — 어느 시안을, 어느 완성도로
  • 브랜드 해석 — 이 브랜드가 뭐여야 하는지
  • 품질 합격 판정 — 체크리스트는 최소한만 걸러줍니다
  • 저작권·보안 판단 — 이 자료를 써도 되는지, 밖으로 내보내도 되는지

AI 말을 그대로 믿으면 안 되는 것

아래 항목들은 AI가 자신 있게 틀립니다. 매번 사람이 확인하세요.

고객사 브랜드 컬러검색 결과랑 실제가 다를 수 있음제공 자료 원본 대조

스킬 결과물에 문서에 없음 — 추정이 붙어 있으면 아직 가설입니다. 고객 확인 전엔 확정하지 마세요.

저작권과 보안

  • 레퍼런스 갤러리는 팀 내부에서 방향 잡을 때 보는 용도입니다. 수집한 이미지를 고객사 제안서나 최종 산출물에 그대로 넣지 않습니다.
  • 레퍼런스에서 가져오는 건 구성 방식이나 여백 운용 같은 원리지, 그 화면 자체가 아닙니다.
  • AI로 만든 이미지는 프롬프트랑 도구명을 적어둡니다. 라이선스 조건이 도구마다 달라요.
  • NDA 있는 프로젝트는 고객사명으로 웹 검색을 하지 않습니다. 산업군이랑 톤 키워드로만 찾으세요.
  • 폰트 라이선스는 꼭 확인하세요. 웹 전용인지, 앱까지 포함인지, 임베딩이 되는지가 계약마다 다릅니다.

1-1 · 기획 문서 분석 /ui-analyze

기획서를 통독하고 화면 리스트를 손으로 정리하던 일이, 요약본 받아서 검증하는 일로 바뀝니다. 읽기가 검증으로 바뀌는 거지 안 읽어도 된다는 뜻은 아닙니다. AI 요약만 믿고 넘어가면 여기서 프로젝트가 틀어져요.

뽑아내는 여섯 가지

  1. 비즈니스 목표 — 이 사이트가 잘됐다는 게 뭘 말하는지. 문서에 여러 개 적혀 있으면 순위를 매기고, 순위가 없으면 그게 첫 번째 확인 질문이 됩니다.
  2. 타겟 사용자와 방문 맥락 — 모바일 비중이랑 첫 방문/재방문 비중은 레이아웃을 결정하니까 꼭 확인하세요.
  3. 화면·기능·콘텐츠 목록 — 이 개수가 곧 일정입니다.
  4. 제약 — 플랫폼, 반응형, 다국어, 접근성, 연동, 브라우저, 일정, CMS.
  5. 디자이너가 챙겨야 할 것 — 아래 표.
  6. 문서에 없는 것 — 이 단계에서 제일 값나가는 산출물.

왜 순서를 바꿨나

지금까지는 화면 다 그리고 나서 디자인 시스템을 정리했습니다. 그건 전 화면을 다시 만지는 일이에요. 시안 전에 정해두면 한 번만 정하면 됩니다. 이 프로세스에서 기존이랑 순서가 달라지는 건 여기 하나뿐입니다.

정하는 것

컬러    원시값 Neutral 8단 + 브랜드 + 의미값 + Semantic
타이포  Display / H1 / H2 / H3 / Body-L / Body / Body-S / Caption / Label
간격    4 또는 8 배수 하나로 — 4·8·12·16·24·32·48·64·96·128
반경    3단 이내      그림자  3단 이내
그리드  01-ui-structure.md 값을 그대로 옮김
  • 값까지 정합니다. "파란색 계열"은 토큰이 아니에요.
  • 원시값(neutral-700)이랑 의미값(text-primary)을 나눕니다. 화면에서는 의미값만 씁니다. 원시값을 직접 쓰기 시작하면 다크모드나 리브랜딩을 못 해요.
  • Neutral 8단을 줄이지 마세요. 부족하면 시안에서 임의 색이 생깁니다.
  • 타이포는 국문 기준으로 정하고 영문을 맞춥니다. 반대로 하면 국문이 깨져요.

2-1 · 컨셉 · 시안 제작 /ui-draft

a. 디자인 컨셉

[대상]에게 [무엇]을 [어떤 방식]으로 보여주는 화면

형용사가 두 개 이상 들어가면 컨셉이 아니라 희망사항이에요. 컨셉에서 디자인 규칙 세 개를 뽑습니다. 시안 만들다 판단이 갈릴 때 쓰는 기준입니다.

b. 컴포넌트 설계

나중에 편집이 편한 시안이 되느냐가 여기서 갈립니다. 화면 먼저 그리고 나중에 컴포넌트로 묶으면 안 묶이는 조각이 꼭 남아요.

화면 목록을 훑어서 두 번 이상 반복되는 요소를 전부 후보로 올립니다.

Core/Button    variant: primary·secondary·ghost / size: l·m·s
               state: default·hover·pressed·disabled / icon: none·leading·trailing·only
Core/Input     state: default·focus·error·disabled / label · helper
Core/Card      variant: default·image-top·horizontal
Core/Badge     Core/Icon
Nav/Header     device: desktop·mobile
Nav/Footer     Nav/Item (default·hover·active)
Feedback/Modal Feedback/Toast
Section/*      프로젝트 전용

variant를 쓰고 컴포넌트를 복제하지 마세요. Button-Primary랑 Button-Secondary를 따로 만들면 수정할 때 전부 따로 고쳐야 합니다.

c. HTML 시안 먼저

Figma에 바로 그리지 않습니다. Figma를 자동으로 조작하는 도구는 사각형, 텍스트, 단색 채우기 정도밖에 못 해요. 말로 된 설명만 보고 좌표를 추측해서 그리면 엉성하게 나옵니다. HTML/CSS로 타이포랑 여백, 대비를 제대로 잡은 화면을 먼저 만들어놓고 그걸 보면서 옮기면 훨씬 정확합니다.

  • 토큰 값을 CSS 변수로 선언하고 그것만 씁니다. 색상 하드코딩 금지.
  • 카피는 기획서의 실제 문구 후보를 쓰고, 없으면 무슨 역할인지 알 수 있는 국문 자리표시 문구를 씁니다. Lorem ipsum은 쓰지 마세요. 국문이랑 길이감이 완전히 달라서 레이아웃 판단이 안 됩니다.
  • 제일 긴 경우랑 제일 짧은 경우를 한 번씩 확인합니다.

d. Figma 이관

기존 컴포넌트랑 스타일을 먼저 확인해서 재사용을 우선하고, 토큰을 스타일이나 변수로 올린 다음, 컴포넌트를 먼저 만들고, 프레임을 오토레이아웃으로 쌓으면서 인스턴스를 배치해 채웁니다.

인계 조건

  • 반복 요소가 전부 컴포넌트 인스턴스. 복사 붙여넣기한 그룹이 없음
  • 모든 프레임에 오토레이아웃
  • 직접 입력한 색상 없음. 전부 스타일이나 변수 연결
  • 텍스트가 텍스트 스타일에 연결
  • Rectangle 42 같은 레이어 이름 없음
  • 프레임 이름이 화면ID_화면명_등급_방향 형식

기술적 한계 고지

한계실제로 일어나는 일어떻게 하나
폰트 지정 불가HTML 시안의 웹폰트가 그대로 안 들어감제일 가까운 기존 스타일 고르고 다르다고 말함
사진 삽입 불가사진이 색상 사각형으로 대체됨플레이스홀더에 규격 표기, 2-3에서 교체

정석 · 무난하게
