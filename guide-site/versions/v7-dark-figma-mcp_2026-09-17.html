    INSTALL

    설치하기

    Claude Code를 열고 저장소를 받는 것까지입니다. 10분이면 끝나고, 한 번만 하면 됩니다.

    준비물

    무엇왜 필요한가
    Claude 데스크톱 앱스킬을 실행하는 도구입니다
    GitHub 계정저장소가 비공개라 초대를 받아야 합니다

    Figma를 연결하려면 준비물이 더 필요한데, 그건 시안을 만들 때만 쓰니까 Figma 연결에서 따로 다룹니다. 먼저 여기부터 끝내세요.

    디자인 도구를 새로 배우는 게 아닙니다. Figma는 쓰던 대로 쓰고, Claude가 옆에서 문서를 읽고 시안을 옮겨주는 구조입니다.

    1 · Claude Code 열기

    Claude 데스크톱 앱을 설치하고 Code 탭을 엽니다. 브라우저로 쓰려면 claude.ai/code로 들어가도 됩니다.

    여기서 말하는 Claude Code는 채팅창이 아니라 내 컴퓨터의 폴더를 열어서 파일을 읽고 쓰는 모드입니다. 이게 있어야 스킬이 돌아갑니다.

    2 · 저장소 받기

    저장소가 비공개라 먼저 초대를 받아야 합니다. 담당자에게 본인 GitHub 아이디를 알려주세요. 초대 메일이 오면 수락합니다.

    https://github.com/gigjoonang/hivelab-ai-process

    받는 방법 두 가지

    ZIP으로 받기 — 저장소 페이지에서 초록색 Code 버튼 ▸ Download ZIP. 압축을 풀면 끝입니다.

    git으로 받기 — 터미널이 익숙하면 이쪽이 낫습니다. 나중에 문서가 바뀌면 git pull 한 번으로 최신으로 맞출 수 있습니다.

    git clone https://github.com/gigjoonang/hivelab-ai-process.git
cd hivelab-ai-process

    폴더는 어디에 둬도 됩니다. 다만 경로에 한글이나 공백이 없는 곳을 권합니다. ~/work/hivelab-ai-process 정도가 무난합니다.

    3 · 폴더 열고 확인하기

    Claude Code에서 방금 받은 폴더를 엽니다. 열면 CLAUDE.md를 자동으로 읽어서 이 프로세스의 규칙이 적용됩니다. 따로 설정할 건 없습니다.

    제대로 됐는지 확인

    입력창에 / 를 쳐보세요. 아래 아홉 개가 목록에 보이면 성공입니다.

    /ui-intake     /ui-analyze    /ui-structure
/ui-style      /ui-tokens     /ui-draft
/ui-assets     /ui-review     /ui-handoff
    안 보이면

    폴더를 한 단계 위나 아래로 잘못 연 경우가 대부분입니다. 연 폴더 바로 안에 CLAUDE.md와 .claude 폴더가 같이 보여야 합니다. .claude는 점으로 시작해서 Finder에서 숨겨져 있을 수 있습니다.

    4 · 첫 프로젝트 돌려보기

    여기까지 됐으면 실제로 한 번 돌려보세요. 끝난 프로젝트의 기획서로 해보는 게 제일 빠릅니다. 결과를 아는 상태에서 보면 스킬이 뭘 잘하고 뭘 못하는지 바로 보입니다.

    # 1. 프로젝트 폴더 만들기
./bin/new-project.sh 고객사명-프로젝트명

# 2. 기획 문서를 넣기
#    projects/고객사명-프로젝트명/source/ 안에
#    PDF든 워드든 PPT든 상관없습니다

# 3. Claude Code에서 실행
/ui-intake

    이후로는 각 스킬이 끝날 때마다 다음 단계를 먼저 물어봅니다. 동의하면 이어서 진행합니다. 전체 순서는 시작하기에 있습니다.

    처음 돌릴 때는 1-4 방향 확정에서 한 번 멈춥니다. 고장난 게 아니라 사람이 골라야 하는 지점입니다. 구조 하나, 스타일 하나를 고르면 이어서 갑니다.

    /ui-draft로 시안을 Figma에 옮기려면 연결이 하나 더 필요합니다. → Figma 연결

    어떤 파일이 뭔지

    폴더를 열면 파일이 많아 보이는데, 처음부터 다 읽을 필요 없습니다. 필요할 때 여는 것만 표시했습니다.

    파일언제 여나
    README.md제일 먼저. 저장소가 뭔지와 시작 방법
    WORKFLOW.md지금 내가 어느 단계인지 확인할 때. 제일 자주 봅니다
    CLAUDE.md사람이 읽는 문서가 아닙니다. Claude가 자동으로 읽는 규칙
    docs/00-principles.mdA급/B급이 뭔지, 저작권·보안 기준이 궁금할 때
    docs/01~03-stage-*.md그 단계를 실제로 할 때. 스킬이 알아서 읽습니다
    docs/quality-bar.md시안이 나갈 만한지 판단할 때
    docs/reference-rules.md레퍼런스를 어디서 몇 장 모으는지
    templates/직접 열지 않습니다. 프로젝트 만들 때 자동으로 복사됩니다
    projects/내 작업물이 쌓이는 곳. 고객사 자료가 들어갑니다
    .claude/skills/스킬 본체. 고칠 일 있을 때만 엽니다

    projects/ 폴더에는 고객사 기획서와 브랜드 자산이 들어갑니다. GitHub에 올라가지 않도록 이미 막아뒀습니다. 이 폴더를 통째로 다른 곳에 복사하거나 공유할 때는 한 번 더 확인하세요.

    막힐 때

    증상보통 이 이유입니다
    스킬 목록에 /ui-*가 안 보인다폴더를 잘못 열었습니다. CLAUDE.md가 보이는 위치인지 확인하세요
    "앞 단계 파일이 비었다"며 멈춘다고장이 아닙니다. 순서를 건너뛴 겁니다. 안내하는 스킬부터 돌리세요
    Figma 관련 문제Figma 연결의 안 될 때 항목을 보세요
    문서랑 이 사이트 내용이 다르다문서가 맞습니다. 이 사이트는 문서를 옮겨둔 것입니다

    그 외에는 Claude에게 그냥 물어보세요. 이 폴더를 열어둔 상태면 문서를 읽고 답합니다.

    문서를 고치고 싶으면

    기준이 현실과 안 맞으면 고쳐야 합니다. 다만 두 가지만 지켜주세요.

    • 어떤 프로젝트에서 무슨 문제가 있었는지 근거를 남깁니다. 근거 없이 바뀐 기준은 다음 사람이 또 바꿉니다
    • 기준은 문서 한 곳에만 둡니다. 스킬 파일로 복사하지 마세요. 복사본은 원본보다 먼저 낡습니다

    고쳤으면 git push로 올리고 팀에 알려주세요. git이 익숙하지 않으면 담당자에게 어디를 어떻게 고쳤는지 전달해도 됩니다.

    INSTALL

    Figma 연결

    Claude가 Figma 파일에 직접 프레임과 컴포넌트를 그릴 수 있게 잇는 설정입니다. /ui-draft로 B급 시안을 옮길 때만 필요하고, 나머지 스킬 여덟 개는 연결 없이도 다 돌아갑니다.

    설치하기를 먼저 끝내고 오세요. 저장소를 받아둔 상태라고 보고 설명합니다.

    빠른 설치

    터미널이 익숙하면 이 네 줄이면 됩니다. 처음이면 아래 설치 항목을 그대로 따라가세요.

    curl -fsSL https://bun.sh/install | bash

git clone https://github.com/grab/cursor-talk-to-figma-mcp.git
cd cursor-talk-to-figma-mcp && bun install && bun socket

    여기에 더해 MCP 서버 등록과 Figma 플러그인 추가가 각각 한 번씩 필요합니다.

    이런 구조입니다

    설정이 네 조각이라 처음엔 복잡해 보이는데, 각각이 뭘 하는지 알면 문제 생겼을 때 어디를 볼지 바로 압니다.

    Claude  ──①──▶  TalkToFigma MCP  ──②──▶  연결 서버  ──③──▶  Figma 플러그인
                                        (localhost:3055)

①  MCP 서버 등록      Claude가 Figma 관련 명령을 쓸 수 있게 됩니다
②  Bun               MCP 서버와 연결 서버를 돌리는 런타임입니다
③  Figma 플러그인      실제로 화면을 그리는 쪽. Figma 안에서 돕니다

    ①은 Claude 설정 파일, ②는 터미널, ③은 Figma 앱. 세 군데를 건드립니다.

    설치

    a. Bun 설치

    MCP 서버와 연결 서버를 돌리는 런타임입니다. 이미 있으면 건너뛰세요.

    curl -fsSL https://bun.sh/install | bash

    설치 후 터미널을 새로 열고 bun --version으로 확인합니다.

    b. MCP 서버 등록

    Claude 설정 파일에 아래 블록을 넣습니다. 파일 위치는 이렇습니다.

    ~/Library/Application Support/Claude/claude_desktop_config.json
    {
  "mcpServers": {
    "TalkToFigma": {
      "command": "bunx",
      "args": ["cursor-talk-to-figma-mcp@latest"]
    }
  }
}

    이미 mcpServers 항목이 있으면 그 안에 TalkToFigma만 추가하세요. 통째로 덮어쓰면 쓰던 다른 MCP가 사라집니다. 넣고 나서 Claude를 껐다 켭니다.

    c. 연결 서버 받아서 실행

    Claude와 Figma 플러그인 사이에서 메시지를 주고받는 작은 서버입니다. Figma로 작업하는 동안 계속 켜둬야 합니다.

    git clone https://github.com/grab/cursor-talk-to-figma-mcp.git
cd cursor-talk-to-figma-mcp
bun install
bun socket

    터미널에 포트 3055로 떴다는 메시지가 나오면 됩니다. 이 창은 닫지 마세요. 닫으면 연결이 끊깁니다.

    d. Figma 플러그인 추가

    Figma 데스크톱 앱에서만 됩니다. 브라우저 버전에서는 안 됩니다.

    Plugins ▸ Development ▸ Import plugin from manifest…

    방금 받은 폴더에서 아래 파일을 고릅니다.

    cursor-talk-to-figma-mcp/src/cursor_mcp_plugin/manifest.json

    플러그인 이름은 Cursor MCP Plugin으로 뜹니다. 이름에 Cursor가 붙어 있지만 Claude에서도 그대로 씁니다.

    연결하기

    설치가 끝나면 이후로는 매번 이 다섯 단계만 하면 됩니다.

    1. 터미널에서 연결 서버가 켜져 있는지 확인합니다 — bun socket
    2. Figma에서 시안을 넣을 파일을 엽니다
    3. Plugins ▸ Development ▸ Cursor MCP Plugin 실행
    4. 플러그인 창에 채널 이름이 뜹니다. 여덟 자리쯤 되는 문자열입니다
    5. Claude에 그대로 말합니다
    1825bhra 피그마 채널에 연결해줘

    연결되면 Claude가 현재 열린 파일의 페이지와 프레임 목록을 읽어서 알려줍니다. 거기까지 나오면 /ui-draft를 쓸 수 있습니다.

    채널 이름은 플러그인을 다시 열 때마다 바뀝니다. 어제 쓰던 이름을 그대로 쓰면 연결되지 않습니다. 매번 플러그인 창에서 확인하세요.

    연결하면 뭘 할 수 있나

    Claude가 쓸 수 있게 되는 기능입니다. 직접 외울 필요는 없고, /ui-draft가 알아서 씁니다. 다만 여기 없는 건 안 된다는 것만 알아두면 기대치가 맞습니다.

    만들기프레임, 사각형, 텍스트, 기존 컴포넌트의 인스턴스 배치

    안 되는 것 — 미리 알아두세요

    한계실제로 일어나는 일어떻게 하나
    폰트 지정서체를 직접 못 고릅니다. HTML 시안의 웹폰트가 그대로 안 들어갑니다파일에 이미 있는 텍스트 스타일 중 제일 가까운 걸 고릅니다
    사진 삽입이미지를 넣을 수 없어 색 사각형으로 대체됩니다규격을 이름에 적어두고 /ui-assets에서 교체합니다
    그라데이션·그림자단색으로 단순화됩니다HTML 시안 이미지를 같이 전달해 의도를 남깁니다

    이 세 가지는 도구의 한계라 고칠 수 없습니다. 그래서 /ui-draft는 Figma에 바로 그리지 않고 HTML로 먼저 만든 뒤 그 이미지를 보면서 옮깁니다. 결과를 공유할 때도 이 한계를 매번 같이 알립니다. 자세한 건 2단계 · 작업을 보세요.

    안 될 때

    증상보통 이 이유입니다
    Claude가 Figma 도구가 없다고 한다MCP 등록(b)이 안 됐거나 Claude를 껐다 켜지 않았습니다
    채널에 연결이 안 된다연결 서버(c)가 꺼졌습니다. 터미널 창을 확인하세요
    어제 쓰던 채널 이름이 안 먹는다정상입니다. 플러그인을 다시 열면 새 이름이 나옵니다
    플러그인 메뉴에 안 보인다Figma 브라우저 버전입니다. 데스크톱 앱에서 열어야 합니다
    연결은 됐는데 엉뚱한 파일에 그린다플러그인을 실행한 그 파일에 그립니다. 원하는 파일을 먼저 열고 플러그인을 실행하세요
    bun: command not foundBun 설치 후 터미널을 새로 열지 않았습니다

    그래도 안 되면 연결 서버를 껐다 켜고(bun socket), Figma 플러그인을 다시 실행한 다음, 새 채널 이름으로 다시 연결해보세요. 대부분 여기서 풀립니다.

    이렇게 하면 안 굴러갑니다

    방향 확정을 건너뛰는 경우

    구조랑 스타일을 안 정하고 시안부터 만들면 시안 개수만 늘고 아무것도 확정이 안 됩니다. 1-4를 넣은 이유가 그겁니다. 형식 때문이 아니라 여기서 비용이 정해져서요.

    파일 안 채우고 대화로만 진행하는 경우

    대화는 세션 끝나면 사라집니다. 다음 사람은 처음부터 다시 하게 되고요. 이 프로세스가 조직에 남기려는 게 그 파일입니다.

    B급 시안을 그대로 고객사에 보내는 경우

    한 번만 이래도 "AI로 대충 만드는 회사" 소리 듣습니다. B급은 내부에서 비교하려고 만드는 거예요.

    PRINCIPLES

    원칙 — AI를 어디까지 쓰나

    프로젝트 사정 따라 바뀌지 않는 것들입니다. 여기랑 다른 얘기가 다른 데 적혀 있으면 이걸 따릅니다.

    대전제

    프로세스를 바꾸지 않습니다. 기존 프로세스 밑에 AI 레이어를 깝니다. 디자이너가 일하는 순서, 산출물 종류, 고객 커뮤니케이션 방식은 그대로고 단계마다 드는 원가랑 시간만 바뀝니다.

    이건 양쪽으로 적용됩니다. AI가 빨라졌다고 단계를 건너뛰지 않고, AI가 못 하는 구간을 억지로 맡기지도 않습니다.

    A급 시안과 B급 시안

    A급 시안B급 시안
    목적고객 제안의 메인 안비교해 보라고 같이 내는 안
    들어가는 것브랜드 해석, 차별화 포인트다른 선택지의 형태
    만드는 사람디자이너가 직접AI가 만들고 사람이 고르고 손봄
    AI의 역할에셋 생성 보조만제작 전체
    고객 전달그대로 나감그대로 나가지 않음
    품질 책임디자이너디자이너 (고르고 손본 결과에 대해)
    흔한 오해

    B급이 A급을 대충 만든 버전은 아닙니다. 원래 시간이 없어서 못 만들고 버렸던 안이에요.

    지금까지는 3안 제안하면 제작비가 3배였습니다. 그래서 대부분 1안만 제대로 만들고 나머지는 구색이거나 아예 안 만들었죠. A급/B급을 나누면 그 등식이 깨집니다. 품질을 낮추자는 게 아니라 볼 수 있는 선택지를 늘리자는 쪽입니다.

    이것만은 지켜주세요

    1. 고객에게 나가는 완성도는 사람이 책임집니다. AI가 만든 건 검수하고 손보기 전엔 고객사로 안 나갑니다.
    2. 앞 단계 파일이 비어 있으면 다음으로 안 넘어갑니다. 앞이 비면 뒤 단계 AI가 알아서 추측으로 채웁니다.
    3. 왜 골랐는지 적어둡니다. 안 적어두면 두 달 뒤에 아무도 기억 못 해요.
    4. 고객사 자료는 저장소랑 승인된 도구 밖으로 안 나갑니다.

    사람이 하는 판단

    이건 AI한테 안 넘깁니다. 넘기면 프로세스를 돌리는 의미가 없어집니다.

    • 방향 결정 — 3안 중 뭘로 갈지 (1-4)
    • 고객에게 나갈 것 고르기 — 어느 시안을, 어느 완성도로
    • 브랜드 해석 — 이 브랜드가 뭐여야 하는지
    • 품질 합격 판정 — 체크리스트는 아래쪽 선일 뿐입니다
    • 저작권·보안 판단 — 이 자료를 써도 되는지, 밖으로 내보내도 되는지

    AI 말을 그대로 믿으면 안 되는 것

    아래 항목들은 AI가 자신 있게 틀립니다. 매번 사람이 확인하세요.

    항목왜 틀리나확인 방법
    고객사 브랜드 컬러검색 결과랑 실제가 다를 수 있음제공 자료 원본 대조
    레퍼런스 URL없는 주소를 그럴듯하게 만들어냄전부 직접 열어보기
    색상 대비 수치계산 안 하고 감으로 말함대비 계산기로 실측
    폰트 라이선스조건을 낙관적으로 기억함제작사 공식 페이지 확인
    기획서에 없는 요구업계 관행을 문서 내용인 것처럼 말함문서 원문 다시 보기

    스킬 결과물에 문서에 없음 — 추정이 붙어 있으면 아직 가설입니다. 고객 확인 전엔 확정하지 마세요.

    저작권과 보안

    • 레퍼런스 갤러리는 팀 내부에서 방향 잡을 때 보는 용도입니다. 수집한 이미지를 고객사 제안서나 최종 산출물에 그대로 넣지 않습니다.
    • 레퍼런스에서 가져오는 건 구성 방식이나 여백 운용 같은 원리지, 그 화면 자체가 아닙니다.
    • AI로 만든 이미지는 프롬프트랑 도구명을 적어둡니다. 라이선스 조건이 도구마다 달라요.
    • NDA 있는 프로젝트는 고객사명으로 웹 검색을 하지 않습니다. 산업군이랑 톤 키워드로만 찾으세요.
    • 폰트 라이선스는 꼭 확인하세요. 웹 전용인지, 앱까지 포함인지, 임베딩이 되는지가 계약마다 다릅니다.

    1-1 · 기획 문서 분석 /ui-analyze

    기획서를 통독하고 화면 리스트를 손으로 정리하던 일이, 요약본 받아서 검증하는 일로 바뀝니다. 읽기가 검증으로 바뀌는 거지 안 읽어도 된다는 뜻은 아닙니다. AI 요약만 믿고 넘어가면 여기서 프로젝트가 틀어져요.

    여섯 가지를 뽑습니다

    1. 비즈니스 목표 — 이 사이트가 잘됐다는 게 뭘 말하는지. 문서에 여러 개 적혀 있으면 순위를 매기고, 순위가 없으면 그게 첫 번째 확인 질문이 됩니다.
    2. 타겟 사용자와 방문 맥락 — 모바일 비중이랑 첫 방문/재방문 비중은 레이아웃을 결정하니까 꼭 확인하세요.
    3. 화면·기능·콘텐츠 목록 — 이 개수가 곧 일정입니다.
    4. 제약 — 플랫폼, 반응형, 다국어, 접근성, 연동, 브라우저, 일정, CMS.
    5. 디자이너가 챙겨야 할 것 — 아래 표.
    6. 문서에 없는 것 — 이 단계에서 제일 값나가는 산출물.

    기존 디자인 시스템이나 브랜드 가이드토큰 새로 만들었는데 못 씀
    접근성 요구 수준대비랑 포커스를 전면 재작업

    실제 사진·영상 자산시안은 스톡인데 실물은 다른 사진
    법적 고지·약관 화면마감 직전에 화면이 추가됨

    1-2 · 구조 · 레이아웃 /ui-structure

    지금까지는 경험으로 1안 잡고 시작했습니다. 이제는 구조 유형 몇 개를 근거랑 같이 비교하고 고릅니다.

    화면 목록 표가 핵심입니다

    | 화면 ID | 화면명 | 뎁스 | 유형 | 반응형 | 상태 변형 | 비고 |

    상태 변형은 빈 상태, 로딩, 에러, 권한 없음처럼 추가로 그려야 하는 화면입니다. 이 칸을 채워야 실제 화면 수가 나와요. 보통 명목 화면 수의 1.3~1.6배가 나옵니다. 이 숫자가 일정의 근거가 됩니다.

    레이아웃 3안

    등급어떤 건가
    정석그 유형의 표준 존 순서. 헤더 → 히어로 → 핵심가치 → 근거 → CTA → 푸터
    변주존 하나를 크게 재배치. 히어로를 빼고 바로 실제 화면이나 상품을 보여주거나, 좌측 고정 내비
    파격스크롤 문법 자체를 바꿈. 가로 스크롤, 풀스크린 섹션 전환, 단일 캔버스

    A·B·C로 부르지 마세요. A급 시안 / B급 시안이랑 헷갈립니다. 회의에서 한 번은 꼭 엉켜요.
